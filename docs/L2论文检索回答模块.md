把工作区右侧的一句中文问话，变成「可点回 PDF 的精读回答」，或「本地库卡片 / arXiv 条目」，闲聊则直接短回。不是把全文塞进一次 prompt，也不是三个并列的提问框。

```text
AskPanel（一个输入框）
  → POST /papers/{id}/ask   { question, history }
  → dialogue（对话层：记忆 + 闲聊/澄清/检索）
       ├─ chat / clarify → 短回 → 结束
       └─ retrieve → plan_tasks（可多选）

            └─ arxiv       Atom / OpenAlex（一轮）        → external_refs
```

教程是一份可逐步执行的 notebook（PDF → Markdown → 切块 → 工具 → 图 → Gradio）。本仓库把同一套控制流接到已有解析与工作区上：**不**再转 Markdown，**不**起 Gradio。第 1–12 节对照教程写 **精读本篇**；对话层、本地库 / arXiv 是教程没有的产品层，放在 §0 与第 13 节。

## 0. 一个入口，三层分工

工作区右侧 `AskPanel` 是**一个**提问入口。HTTP 仍是 `POST /papers/{id}/ask`（也可直打 `/library/ask`、`/arxiv/ask`）。「一个入口」只保证 UI 不分裂。Agent 模式进 LangGraph 之后分成三层，**不再**在进图前用正则三选一切整条流水线。

| 层 | 干什么 | 不干什么 |
|---|---|---|
| **对话层** `dialogue` | 看见近期原文；判定 chat / clarify / retrieve；检索时写出独立任务 | 不搜 chunk、不写精读 `[n]` |
| **计划层** `plan_tasks` + `Send` | 把任务派到本篇 / 本地库 / arXiv（可并行） | 不再读聊天记录 |
| **取证层** | 精读走 Worker 循环；库 / arXiv 各走一轮流水线 | 不猜「它」是谁 |

三种**证据世界**的引用契约仍然分开，只是可以同一轮同时取：

| 任务 kind | 何时 | 证据从哪来 | 回答里带什么 |
|---|---|---|---|
| `close_read` | 默认；问当前这篇 | 本篇 Parent–Child + LangGraph Worker | `citations`（节名+页码，可跳 PDF） |
| `library` | 「我之前研读过…」「本地库」 | 已索引的其它本地论文卡片 | `library_hits`（可「进入这篇」） |
| `arxiv` | 「在 arXiv 上检索相关论文」等 | 官方 Atom API，超时则 OpenAlex | `external_refs`（不是本篇页码） |

对话层 intent：

| intent | 例子 | 接着做什么 |
|---|---|---|
| `chat` | 「你是干什么的」 | 固定口径短回，不进 Worker |
| `clarify` | 首句就问「那个呢」且上文补不出 | 反问一句，不进 Worker |
| `retrieve` | 方法、这个 λ、库里还有类似的吗 | 进计划层 |

身份类由 `is_obvious_chat` 正则直接 `chat`，不打对话 LLM。其余问句走 `DialogueAct`；`suggest_task_kinds` 只在模型没给出 kinds 时做缺省（可多选，不再互斥）。「这篇的相关工作」仍钉在精读；「在 arXiv 上检索相关论文」走外部。混合句（「这篇方法和库里那篇差在哪」）计划层同时 Send 两路，最后按袋组装。

这和「精读里的多 Agent」不是同一层：

| | 对话层 + 计划层 | 精读 Worker |
|---|---|---|
| 判定什么 | 要不要检索、去哪个证据世界、问句是否自包含 | 本篇里补 Child / Parent / 图 / 译文 |
| 何时 | 主图入口 | 只在 `close_read` 任务里 |
| 怎么判 | 正则闲聊 + LLM `DialogueAct`；kinds 可回落到 `suggest_task_kinds` | Orchestrator + 工具 |
| 错了会怎样 | 闲聊被拿去检索，或跟进指代没补全 | 检索偏了、漏节，但仍在本篇里 |

simple 模式没有对话层：`ask()` 仍用 `suggest_task_kinds` 决定精读 / 库 / arXiv / 混合拼接。Agent 模式才走 `dialogue` → `Send`。

漏匹配默认精读。`[n]` 只对本篇页码，库命中是进篇卡片，外部条目是链接。库 / arXiv **不**进精读 Worker 工具箱。

## 3. 嵌入模型设置

**作用：**

- **稠密嵌入**：神经网络捕捉语义（近义 / 改写）
- **稀疏嵌入**：BM25 关键词（专名、符号、λ、HRNet）

对照教程 HuggingFace `all-mpnet-base-v2` + FastEmbed `Qdrant/bm25`。首次索引会下载权重，需要能访问模型源或已有缓存。

| 路 | 默认 | 擅长 | 不擅长 |
|---|---|---|---|
| 稠密 | `sentence-transformers/all-mpnet-base-v2`（768 维） | 「优化目标」≈「损失函数」 | 精确专名 |
| 稀疏 | FastEmbed `Qdrant/bm25` | 词面命中 | 同义改写 |

也可改用云端 `EMBEDDING_MODEL` + `EMBEDDING_BASE_URL` 代替本地稠密模型。两路都就绪才构造 `HybridEncoder`；缺一路则整篇 `embedding_version=lexical-v1`，`query` 走 `retrieve_from_chunks`。

```47:60:src/dl_agent/knowledge/adapters/vector/hybrid_embed.py
def try_hybrid_encoder(settings: Settings) -> HybridEncoder | None:
    sparse_docs, sparse_query = _try_fastembed_sparse(settings.sparse_model)
    if sparse_docs is None or sparse_query is None:
        return None
    dense_docs, dense_query = _try_dense(settings)
    if dense_docs is None or dense_query is None:

        dense_query,

        sparse_query,
```

稠密维数必须和建 collection 时写死的 `size` 一致。换模型会换 `embedding_version`，进而换 Qdrant collection 名，避免旧向量混用。

## 4. 向量数据库配置

**作用：**

- 初始化本地、基于文件的 Qdrant 客户端
- 一张表同时存稠密、稀疏向量
- 检索时两路分数用 **RRF** 融合

对照教程 `QdrantClient(path=...)` + LangChain `QdrantVectorStore(RetrievalMode.HYBRID)`。本仓库**不**再包 LangChain VectorStore，实现在 `knowledge/adapters/vector/`（生产用 Qdrant，单测用 `MemoryVectorIndex`）。

- 路径：`QDRANT_PATH` 或 `{DATA_DIR}/qdrant`
- collection 名：`{QDRANT_COLLECTION}_{embedding_version}`，换模型不和旧向量混用
- 每条向量带 `paper_id` / `chunk_id` / `section_id` / `section_kind`，检索时过滤，禁止串篇

稠密用命名向量 `dense`（余弦），稀疏命名 `sparse`。查询侧 `prefetch` 两路，再 `Fusion.RRF`：

```80:117:src/dl_agent/knowledge/adapters/vector/qdrant_index.py
    def search_hybrid(...):
        ...
        result = self.client.query_points(
            collection_name=self.collection,
            prefetch=[
                rest.Prefetch(**prefetch_kw),   # 稠密
                rest.Prefetch(**sparse_kw),     # BM25
            ],
            query=rest.FusionQuery(fusion=rest.Fusion.RRF),
            limit=limit,
        )
```

词法回退里的 RRF 在 `retrieve.rrf_merge`：`score = Σ 1/(k+rank)`，`k=60`。Hybrid 失败或没命中，再走词法，保证总能给出袋，而不是空 500。

教程每次重跑索引会 `delete_collection` 再建。这里按 `paper_id` 删点再 upsert，其它论文不受影响。

## 5. 论文解析（对照「PDF 转 Markdown」）

**作用：** 教程 §5 用 PyMuPDF4LLM 把 PDF 转成 `.md`，再按 `#` / `##` 切 Parent。

本仓库解析已经在 ingest 完成：`Section` 带 `section_id`、`kind`、页码、配图。**不为 RAG 再转 Markdown**，否则会丢掉公式处理和图绑定（L1 的产出就是问答的 Parent）。

Parent = 一节 `Section`（过长在取 Parent 时截断到 4000 字）。Child = 从该节滑窗切出的 500 字块。章节边界以解析结果为准，不合并过小节、不把大节再切成第二套 Parent。

## 6. 文档索引

**作用：**

- 用父子分块在检索精度和上下文之间做平衡
- **父块**：大窗口（一节全文，取回时最多 4000 字）
- **子块**：小检索单元（约 500 字符，overlap 100），写入 Qdrant

对照教程：父块 2000–4000 字存 JSON，子块 500/100 进向量库；过小合并、过大再切。这里不做那套 merge/split：解析已经按标题切开，再并会把 Method 和 Intro 糊在一起，引用页码也会漂。

滑窗切 Child，优先在段落或空格处断开：

```14:47:src/dl_agent/knowledge/chunk.py
def chunk_text(text: str, size: int = 500, overlap: int = 100) -> list[str]:
    ...
    while start < len(blob):
        end = min(len(blob), start + size)
        if end < len(blob):
            end = _prefer_break(blob, start, end, size)  # 先找 \n\n，再找空格
        ...
        start = max(end - step_overlap, start + 1)
```

`build_chunks` 跳过 references / 致谢。块太多时 `cap_chunks`（默认最多 800）优先丢掉 other / related。每块 `chunk_id` 形如 `sec-012:3`，后面取 Parent 就靠前面的 `section_id`。

`index_paper`（解析完成后自动，或 `POST /papers/{id}/index`）：

1. `build_chunks` → `cap_chunks`
2. 有向量后端则按 `paper_id` 删旧点再 upsert；始终写 `chunks.json` + manifest
3. `source_hash` + `embedding_version` 没变则跳过（`force=true` 才重建）
4. `index_status=ready | skipped | failed`

`query(paper_id, question, k)`：Hybrid 有命中用 RRF Top-k；否则词法。中文问英文论文时，词法路会回退到 method / intro 等节（`_FALLBACK_KINDS`），避免空袋。`paper_id` 过滤写在 Qdrant payload 上，模型不能指定搜全部论文。

`needs_ocr` 或没有可切正文 → `skipped`，问答返回 `no_evidence`，对照阅读不受影响。

## 7. 定义工具

**作用：**

- `search_child_chunks`：在向量库里搜相关小块（快、语义检索）
- `retrieve_parent_chunks`：按 `section_id` 取该节全文（完整上下文）

- 问句含拉丁词：词项须出现在摘录或节名，否则视为 `NO_RELEVANT_CHUNKS`
- 纯中文问句：不做词面过滤（产品主路径是中文问英文论文）

## 8. 系统提示词

**作用：** 约束各节点。全文在 `understand/agent/prompts.py`。对照教程的英文 Prompt，这里多了对话调度和记忆压缩。

| 提示 | 职责 | 对照教程 |
|---|---|---|
| `dialogue_prompt` | 调度器：chat / clarify / retrieve；retrieve 时写出独立 `AskTask` | 查询改写升成对话层；**不**搜论文 |
| `dialogue_memory_compress_prompt` | 更早轮次压成 150–250 字中文笔记，对着当前句取舍 | 对话摘要；这里**不**列 PDF 文件名 |
| `orchestrator_prompt` | 先看已搜 Child；太碎取 Parent；缺细节换英文 query 再搜；可目录 / 图注 / 译文 | 编排器（只在精读 Worker） |
| `compress_prompt` | Worker 超 token 时压成研究笔记（Focus / Findings / Gaps） | 上下文压缩；按**章节标题**组织 |
| `fallback_prompt` | 触顶后只用已有笔记和工具结果作答 | 兜底 |
| `aggregation_prompt` | 子答案 + 编号证据 → JSON：`answer_zh` / `used_evidence` / `partial` | 汇总；Sources 改成程序映射的 `[n]` |

`rewrite_query_prompt()` 仍是 `dialogue_prompt()` 的别名，避免旧测试名断裂。

关键行为（和教程对齐的部分）：

- 检索任务尽量自包含；专名、符号、数据集名原样保留
- Orchestrator 先看压缩记忆，已搜过的 query / 已取过的 `section_id` 不要重复（运行时还有 `retrieval_keys` 去重）
- 找不到就换英文 query 再搜，或建议去 method / experiment
- 触达上限走兜底，只用已检索内容
- 公式保持证据里的 `$...$` / `$$...$$`，不要改成 Unicode

和教程刻意不同：

- 中文精读口径；不要写 Sources 文件名；编号由程序映射成 `Evidence`
- 含糊问句走 `clarify` **短回**，不再把原问题硬塞进 Worker
- 「回到这篇 / 本文方法」钉 `close_read`，不要沿用上一轮搜库 / arXiv
- 不要把 Front Matter / 标题页拿来撑实验结论
- 缺信息一两句「原文未给出」带过，不要单独开「尚未覆盖」清单

native 协议下 Orchestrator 直接调提供的工具；json 协议只输出一个 `{"tool":...}` 对象。

## 10. Agent 上限与 Token

**作用：** 防止空转烧 token。对照教程 `MAX_TOOL_CALLS` / `MAX_ITERATIONS` / `tiktoken`。

| 配置 | 默认 | 行为 |
|---|---|---|
| `ASK_MAX_TOOL_CALLS` | 6 | 含强制首搜；触顶 → fallback |
| `ASK_MAX_ITERATIONS` | 8 | 进入 Orchestrator 的次数触顶 → fallback |
| `ASK_COMPRESS_TOKENS` | 2000 | `chars//4` 估算超了就压缩再回 Orchestrator |
| `ASK_MAX_SUBQUESTIONS` | 3 | 精读 `close_read` 任务条数上限（会给库 / arXiv 留名额） |

教程用 `tiktoken` 统计 `msg.content`。这里不引入 tiktoken：`estimate_tokens` 把消息和压缩笔记的字符数除以 4。压缩阈值是固定 2000，没有教程那种 `TOKEN_GROWTH_FACTOR` 随摘要变长放宽窗口。

`tool_call_count` / `iteration_count` 用 `operator.add`：节点 `return {"tool_call_count": 1}` 表示「这次 +1」，不是把总数写成 1。

## 11. 图节点与逻辑

**作用：** 对照教程 §11。节点在 `nodes.py`，边在 `edges.py`。

教程核心节点：`summarize_history` → `rewrite_query` →（不清则 HITL）→ 并行 `orchestrator` 循环 → `aggregate_answers`。本仓库主图改成 **对话层先拍板**：`dialogue` → chat/clarify 走 `direct_reply`，retrieve 再 `Send`。精读 Worker 循环仍**写死首搜**，并且模型想直接定稿时**强制取一次 Parent**。库 / arXiv 任务进同一 `worker` 节点，但走一轮流水线，不进 Orchestrator 循环。

### Worker（一条子问题）

### 本地库

`ask_library`：在已索引论文里按标题/摘要/切块检索（`query_corpus`），排除当前打开的一篇。命中做成卡片，模型只根据卡片写中文。`library_hits` 可点「进入这篇」。无命中时固定口径，不编造。Agent 图里由 `library_worker_node` 调同一流水线，**history 传空列表**（问句已由对话层写自包含）。

直打：`GET /library/search`、`POST /library/ask`。

### arXiv / OpenAlex

`ask_arxiv`（`arxiv-ask-v2`）：

1. 问句里若有 `2303.08774` 这类 id，按 id 取元数据。
2. 否则从当前论文的标题、首页标题节、摘要抽出主题；LLM 改写成 1 条英文检索句（任务/方法术语，不要整句复述标题，不要把专有系统名当唯一检索词）。
3. `mcp_gateway` 调 `export.arxiv.org` Atom API（默认 8s、不跟系统代理；超时再试一次直连）。过滤 `withdrawn` / `removed`。
4. 官方接口仍不可用时，回落到 [OpenAlex](https://api.openalex.org/works) 书目检索。OpenAlex 不是预印本托管站：条目常是 DOI / 出版社链接，不一定带 arXiv id。
5. 丢掉与当前论文相同的 id/标题；只剩自己则固定口径。
6. 模型根据编号条目写中文综述。命中进 `external_refs`。Agent 图里由 `arxiv_worker_node` 调用，同样不传 history。

直打：`POST /arxiv/ask`。无主题（没打开论文、问句也没有关键词）返回 `NEED_ARXIV_TOPIC` 口径。连不上官方且 OpenAlex 也失败时：「暂时连不上 arXiv」。

## 15. 一次提问实际走了什么

以工作区问「核心方法是什么？」为例（`ASK_MODE=agent`，索引 `ready`）：

```text
AskPanel
  → POST /papers/{id}/ask  { question, history }
  → ask_agent（纯精读才校验 index ready）
  → dialogue
       pack_dialogue_memory（首问则空）
       DialogueAct → retrieve / close_read
       plan_tasks = [{kind: close_read, question: 自包含问句}]
  → Send worker
       强制 search_child_chunks（中文问句保留 Top-k）
       Orchestrator：native/JSON 取 Parent，或运行时强制取 method/approach 节
       可选再搜 / list_sections / 图注 / 压缩 / fallback
       collect_answer + evidence_bag
  → 聚合 JSON → used_evidence 映射 citations
  → _verify_quote（摘录须是该节子串）
  → PaperAnswer.answer_zh + 引用芯片
```

问「你是干什么的」：

```text
AskPanel → POST /papers/{id}/ask
  → is_obvious_chat → dialogue skip_workers
  → direct_reply（固定身份口径）→ 不进 Worker、不查索引
```

```text
AskPanel → POST /papers/{id}/ask
  → dialogue → retrieve / arxiv
  → Send worker.kind=arxiv（一轮流水线，不进 Orchestrator 循环）
  → 标题/摘要改写英文 query
  → Atom API（失败则 OpenAlex）
  → 过滤撤回、丢掉本篇自己
  → 综述进 agent_answers；aggregate 原样带出 external_refs
```

问「这篇方法和库里那篇差在哪」（混合）：

```text
dialogue → plan_tasks 同时 close_read + library
  → 并行：精读 Worker 循环 + 本地库一轮
  → aggregate：本篇 citations 与 library_hits 同袋；
```

## 17. 和教程刻意不同的点

1. 精读仍是单篇 `paper_id`；Sources 是节名+页码。本地库 / arXiv 是计划层可并行的任务，不进精读工具箱。  
2. Parent 是 `Section`，不是 `parent_store/*.json`；不为 RAG 再转 Markdown。  
3. 无 0.7 阈值；中文问句不过度词面过滤。  
4. 无 HITL、无 Gradio、无 Ollama 必依赖；Langfuse 可选，无密钥不上报。含糊句由对话层 `clarify` 短回。  
5. 默认 native OpenAI tools；Gemini / 400 回落 JSON。强制首搜 + 未取 Parent 时强制取一次。  
6. 空袋不编造：`no_evidence` 固定口径。  
7. 可 `ASK_MODE=simple` 降级，HTTP 字段不变。  
8. arXiv 官方超时后走 OpenAlex 书目检索，不是第二个预印本站。  
9. 跨请求不用 checkpointer：多轮靠前端传来的 `history`；Agent 窗口化压缩更早轮次，近 4 条原文保留。

## 19. 已知边界（不是 bug 清单，是产品范围）

这些是实现里**故意不做**或**只做到这一步**的地方：

- **一个入口、可并行的证据世界**：模糊句（「还有没有类似工作？」）默认精读本篇 Related Work，不会自动上网或翻库；双边问句（这篇 + 库）才同时 Send。
- **无 HITL**：含糊句由对话层 `clarify` 反问一句，不打断等人填表。
- **无过程流式**：不把 tool 调用推到 UI；一次返回 `PaperAnswer`。
- **不看图像素**：图工具只给题注和邻近摘录。
- **精读不跨篇**：Worker 的 `paper_id` 绑死；跨篇是 library 任务。
- **默认不在精读 Worker 里搜 arXiv**：`ASK_ENABLE_EXTERNAL` 默认关。
- **索引 pending 不锁输入**：前端只提示；纯精读 409，闲聊 / 库 / arXiv 仍可走。
- **simple 降级**：一次检索 + 一次生成，没有对话层、扇出和强制 Parent。
- **OpenAlex 不是 arXiv 镜像**：超时回落只有书目，可能没有 pdf 链接。
- **单机 Qdrant 文件库**：无云端 collection；换 embedding 靠分表，不自动迁移旧向量。
