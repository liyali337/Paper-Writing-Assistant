# M1 按标题分解 + 抽图 代码解读

对应实现：`src/dl_agent/knowledge/` 为主，薄 HTTP 在 `src/dl_agent/api/`。对齐 `docs/论文理解-技术方案.md` 第 9 节 M1：上传 PDF 后按 heading 切成 `Section`，插图裁成 PNG 挂到当前节。

本期**不生成**中文总体介绍 / 方法详解（那是 M2）。解析完成后 `intro_status` / `method_status` 记为 `skipped`，关掉 LLM 仍可看章节原文和图。

开发：

- 前端：`http://localhost:5173/`（`npm run dev:web`）
- API：`http://127.0.0.1:8000/`（`dl-agent-api` 或 `npm run dev:api`）

## 1. 这次写了什么、下载了什么

### 1.1 新下载的包

M0 已经有 FastAPI / uvicorn / pydantic。M1 新装的是解析栈：

| 包 | 版本（本机） | 用途 | 怎么装的 |
|---|---|---|---|
| **PyMuPDF**（`pymupdf`） | 1.28.2 | 校验 PDF、加密检测、降级抽字、xref 抽图、题注邻域 clip | `pip install pymupdf`，并写入 `pyproject.toml` 主依赖 |
| **Docling** | 2.121.0 | 主路径：关 OCR、开 `generate_picture_images`，一次 convert 出标题树 + 插图 | `pip install "docling>=2.50"` |

Docling 会**连带**拉一批很大的科学计算 / 视觉依赖（不是我们手写进去的）：

| 连带包（不完全） | 干什么 |
|---|---|
| `torch` / `torchvision` / `transformers` | 版面检测、表格结构模型 |
| `docling-core` / `docling-parse` / `docling-ibm-models` | 文档对象、PDF 后端、IBM 版面模型 |
| `pillow` | 把 `PictureItem` 存成 PNG |
| `pypdfium2` / `rapidocr` | PDF 渲染；OCR 引擎在包里，**我们调用时 `do_ocr=False`，不跑 OCR** |
| `numpy` / `scipy` / `pandas` / `opencv-python` | 模型与图像处理 |

第一次对真实论文跑 Docling 时，Hugging Face 还可能再下一份 **layout / table 模型权重**（缓存到本机 Hugging Face 目录），之后不用重复下。

**明确没装 / 没用的：**

- 没有 GROBID / Java / scipdf
- 没有 Qdrant、embedding、LLM SDK（讲解是 M2）
- 没有 Postgres 驱动：M1 元数据用本地 JSON，对象文件用目录，不启 `deploy/docker-compose.yml`
- 前端没有新的 `npm install`

## 3. 主路径（一次上传发生了什么）

```text
POST /papers  multipart file
  → 扩展名 .pdf、%PDF 头、≤50MB、未加密
  → sha256：命中且已终态 → 直接返回旧 paper_id（不重解析、不重裁图）
  → 否则写入 source.pdf，status=queued，立刻返回 {paper_id, status}
  → BackgroundTasks.finish_ingest
        status=parsing
        parse_pdf()：
            Docling（do_ocr=False, generate_picture_images=True, timeout=120s）
            文本过少 / 超时 / 崩溃 → PyMuPDF
            有题注无图 → 题注上方 clip（source=page_clip）
        assemble()：heading 开新节，picture 挂当前节
        宽或高 < 80px 丢弃（logo）
        References 之后的附录与图不再入库
        全文 <800 字或每页 <200 字 → needs_ocr，不调 LLM
        否则 status=ready；intro/method = skipped
  → UI 轮询 GET /papers/{id}
        ready | needs_ocr → GET /sections、GET /figures
        <img> GET /figures/{fid} 取 PNG
```

同步语义：API **先返回再解析**。前端本来就按任务轮询，不必卡在 `uploadPaper()` 上干等 Docling。

## 4. 各文件在干什么

### 4.1 `config.py`

`pydantic-settings`，环境变量前缀 `DL_AGENT_`。缺省：

| 项 | 默认 | 含义 |
|---|---|---|
| `data_dir` | `./data` | 论文与图的根目录 |
| `max_pdf_bytes` | 50MB | 上传上限 |
| `docling_timeout_s` | 120 | `document_timeout` |
| `images_scale` | 2.0 | 裁图分辨率 |
| `min_figure_px` | 80 | 过小图过滤 |
| `min_chars_total` / `min_chars_per_page` | 800 / 200 | 扫描件门禁 |

单测把 `data_dir` 指到 `tmp_path`，不污染仓库。

### 4.2 `pdf_io.py`

- 不是 `%PDF`、打不开、加密且空密码失败 → `InvalidPdfError` → HTTP 400 `invalid_pdf`
- `sha256_bytes` 做去重键

### 4.3 `classify.py`

纯规则，不调模型：

- `3. Method` / `III. OUR APPROACH` → `kind=method`
- Abstract / Intro / Related / Experiment / Conclusion / References 同理
- 题注：`^(fig(?:ure)?|table|algorithm)\s*\.?\s*\d+`
- `Acknowledgements` 整节丢掉
- 编号深度 `1.2.3` → `level=3`

### 4.4 `layout.py`（切节核心）

适配器只输出统一的 `LayoutItem`（`heading` / `text` / `table` / `picture` / `caption`）。`assemble()` 按阅读序：

1. 遇到 heading：关掉同级或更高级的节，开启新 `Section`，记 `page_start`
2. 正文、表格 Markdown、题注写入**当前未关闭的节**
3. `picture` 通过宽高过滤后生成 `Figure`，`section_id` = 当前节，PNG 放进 `figure_pngs`
4. 页 1 上未编号、且不像章节名的第一行当作论文标题，不当成一节
5. 看到 `References` 后：保留参考文献正文，后面的附录标题和图全部丢掉

测例 `test_layout.py` 不需要真实 PDF：heading A → 图 → heading B → 图，断言两张图分别挂 A/B。

### 4.5 `adapters/pdf/docling_adapter.py`

```text
PdfPipelineOptions(
  do_ocr=False,
  do_table_structure=True,
  generate_picture_images=True,
  images_scale=2.0,
  document_timeout=120,
)
DocumentConverter.convert(pdf)
iterate_items()
```

- `section_header` / `title` → heading
- `PictureItem.get_image()` → PNG 字节，`caption_text` 作题注，`source=docling_picture`
- `TableItem` → Markdown 进节文本，**不另存表图**
- 页眉页脚跳过

一次 convert 同时服务章节和图，禁止为抽图再转一遍。

### 4.6 `adapters/pdf/pymupdf_adapter.py`

Docling 没有或失败时用。`page.get_text("dict", sort=True)`：

- 字号明显高于中位、或匹配常见节名 → heading
- 块类型为图 → xref 抽 PNG，`source=pymupdf_xref`
- 图下方 / 上方约 80pt 扫 `Figure N`
- `clip_missing_captions`：页上有 `Figure N` 题注但没有对应图 → 题注上方约 280pt `get_pixmap(clip=...)`，`source=page_clip`；仍失败则只留题注记录、`storage_key=null`

### 4.7 `adapters/pdf/__init__.py`

门面：先 Docling；字符数够就（可选）再 clip 补矢量图；不够或异常则整篇改走 PyMuPDF。两边都失败才 `ingest_failed`。

### 4.8 `store.py`

没有 Postgres。一篇论文一个目录，键按以后接 S3 的样子写：`papers/{id}/figures/{fid}.png`。`index.json` 把 sha256 映射到 `paper_id`。重新解析同一 id 时先删旧 figures 再写。

### 4.9 `knowledge/service.py`

编排：

1. `start_ingest`：校验、去重、落盘、`queued`
2. `finish_ingest`：parse → assemble → 存 sections/figures → 统计字符决定 `ready` 还是 `needs_ocr`
3. M1 把 intro/method 标 `skipped`，**不调用** `understand.build_*`

`parse_fn` 可注入，所以 ingest 单测用假 `LayoutItem`，不必每次加载 Docling 模型。

日志打 `paper_id`、parser、页数、节数、图数、字符数；不打章节全文。`audit.jsonl` 记 parse 耗时。

### 4.10 `api/routes/papers.py`

| 方法 | 路径 | M1 |
|---|---|---|
| POST | `/papers` | 上传，返回 `paper_id` + `status` |
| GET | `/papers/{id}` | 元数据、解析状态、`figure_count` |
| GET | `/papers/{id}/sections` | 章节树（含 `figure_ids`、页码） |
| GET | `/papers/{id}/figures` | 图清单；`?section_id=` 过滤 |
| GET | `/papers/{id}/figures/{fid}` | `FileResponse` PNG；无文件 404 |
| GET/POST | `/intro` `/method` | 仍 501，文案写明 M2 |

错误体统一 `{code, stage, message}`，和前端 `HttpError` 对齐。

### 4.11 前端为 M1 改的三处

M0 界面已经能轮询。M1 只让「有章节、有原图」看得见：

- `Outline`：节下最多 3 张缩略图，点击跳到该页并打开灯箱
- `IntroPanel` 无 intro 时：按节列出抽出的 PNG，并说明讲解在下一阶段
- `Workspace`：`status=ready` 就结束等待骨架（不再死等 intro）；`needs_ocr` 也会拉 sections，并显示「换可复制文本的 PDF」

## 5. 和前端怎么接

```text
选 PDF
  → 本地 blob 立刻进 iframe（不必等解析）
  → POST /papers
  → 轮询 GET /papers/{id}
        queued|parsing → 顶栏「解析中」
        ready → GET /sections 、 GET /figures
                目录出标题 + 页码 + 缩略图
        needs_ocr → 同上拉章节（可能很空）+ 红色说明
        ingest_failed → 「解析失败」
  → <img src="/api/papers/{id}/figures/{fid}">
```

`intro` / `method` 仍 501。顶栏芯片会显示「介绍跳过 / 方法跳过」，右侧介绍 Tab 用已抽出的图填空，不假装生成了一篇中文报告。

## 6. 和方案文档的差异（有意为之）

| 方案原文 | M1 实际 |
|---|---|
| 元数据 PostgreSQL | 本地 JSON。接口形状不变，M2 再换库也不改路由 |
| 解析进程与 API 隔离 | 同进程 + FastAPI BackgroundTasks。OOM 隔离留到以后 |
| ≤20 页 POST 等到 ready | 一律先返回 queued，UI 轮询（前端本来如此） |
| 上传后自动生成 intro/method | 标 `skipped`，等 M2 |

抽图验收口径没打折：必须是 PDF 裁出的 PNG，不是模型手绘；抽到 0 张图仍 `ready`，只是 `figure_count=0`。

## 7. 怎么看、怎么验

```bash
# 终端 1
npm run dev:web

# 终端 2
source .venv/bin/activate
dl-agent-api
```

浏览器 `http://localhost:5173/`：

1. 拖入一篇 **可复制文本**、最好带方法架构图的英文会议 PDF（建议 ≤15 页）。
2. 顶栏应变为「已分解 · N 图」；左侧目录出现 Abstract、至少一个 Method 类标题、页码。
3. 有图的节应出现缩略图；点击能放大，地址是 `/api/papers/.../figures/...`。
4. 扫描件 / 纯图片 PDF：应提示需要文本型 PDF，**不会**出现假介绍。
5. 同一文件再传一次：应立刻回到已有 `paper_id`，不重裁。

无 UI 的回归：

```bash
.venv/bin/pytest tests -q
```

当前 13 项应全绿。其中 `test_layout` / `test_ingest` / `test_papers_api` 用假解析器，不加载 Docling 权重；`test_pymupdf_adapter` 现场生成一页带图的小 PDF。
