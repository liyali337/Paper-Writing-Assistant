# 论文分析方法综述

本文梳理「用 AI 分析一篇论文 PDF」的常见技术路线、代表开源项目，以及本仓库 [`论文理解-技术方案.md`](论文理解-技术方案.md) 的取舍。面向产品设计与 M2 实现，不展开具体代码。

更细的单项目调用链见 `refs/*技术方案介绍.md`；功能清单见 [`refs/功能介绍.md`](../refs/功能介绍.md)（`refs/` 为本地参考快照，不参与构建）。

---

## 1. 问题定义

「分析论文」在本语境下指：用户上传（或指定）一篇 PDF 后，系统产出**可阅读、可验收**的理解材料，而不是简单把 PDF 转成 Markdown。

常见交付形态：

| 形态 | 用户得到什么 | 典型问题 |
|---|---|---|
| **结构化报告** | 固定栏目的中文/英文摘要（问题、方法、实验…） | 这篇在解决什么？怎么做？ |
| **分块讲解** | 按段落/难度逐块展开 | 某一段看不懂 |
| **问答** | 针对论文的自由对话 + 引用 | 损失函数是什么？和 XX 比呢？ |
| **批量初筛** | 多篇 arXiv 速读卡 | 今晚该精读哪几篇？ |
| **仅解析** | 章节树、图、表、元数据 | 下游 RAG / 精读的前置步骤 |

一条完整链路通常包含三层，可单独存在，也可组合：

```text
解析（PDF → 结构）  →  组织（选什么喂模型）  →  生成（LLM 产出什么）
```

## 2. 方法分类总览

按**「如何把论文内容交给 LLM」**划分，主流方法如下。

| 编号 | 方法 | 一句话 | 复杂度 | 方法细节保真度 |
|---|---|---|---|---|
| M1 | 全文一次生成 | 整篇转文本，一次 prompt 出报告 | 低 | 低（长文易截断） |
| M2 | 整 PDF 多模态 | PDF 字节/base64 直接给 VLM | 低 | 中（黑盒，难挂页码） |
| M3 | 按论文章节名切段 | Abstract/Method/Conclusion 各调一次 LLM | 中 | 中（节名匹配 fragile） |
| M4 | 按输出章节选原文 | 先定报告结构，再为每节匹配 PDF 小节 | 中 | 中高 |
| M5 | Map-Reduce 切块 | 按字符/段落切块 → 每块摘要 → 合成 | 中 | 中（块边界可能断语义） |
| M6 | 分块笔记 + 多路专题 | 先切块做 JSON 笔记，再并行写背景/方法/实验等 | 高 | 高 |
| M7 | 章节树 + 分路结构化 JSON | 按标题分解 + 介绍/方法分开生成 + 步骤挂图 | 中高 | 高（可验收页码/图号） |
| M8 | 检索增强问答（RAG） | embedding 或规则选段，按问回答 | 中高 | 取决于检索质量 |
| M9 | Agentic RAG | 多轮检索、引用图、元数据 enrichment | 高 | 高（偏问答，非固定报告） |
| M10 | 纯解析（无 LLM 讲解） | 只产出 Section/Figure/Table | 中 | N/A（讲解在下游） |

```text
保真度 / 工程成本
     ↑
 M6 PaperPilot ──────────────── M9 PaperQA2
     │                              │
 M7 本仓库候选 B ─── M4 Paper-Copilot
     │                    │
 M3 ChatPaper ─── M5 paper2md
     │
 M2 PaperIQ ─── M1 SmartPaper
     │
     └────────────────────────────→ 实现成本
```

## 3. 解析层：PDF 怎么变成「可读结构」

讲解质量上限由解析决定。常见解析策略：

### 3.1 纯文本抽取

| 手段 | 工具/项目 | 优点 | 缺点 |
|---|---|---|---|
| 按页拼接 | PyPDF2、PyMuPDF `extract_text` | 快、无 GPU | 双栏错序、丢结构、无可靠页-节对应 |
| 全文抽取 | pdfminer、MarkItDown | 实现简单 | 同上，适合短文或批处理 |

**适用**：SmartPaper、ChatPaper 主路径、Research-QA-Assistant、Explainer。

### 3.2 学术 TEI / GROBID

| 手段 | 工具/项目 | 优点 | 缺点 |
|---|---|---|---|
| GROBID HTTP | scipdf_parser、OpenChatPaper | 题名/作者/参考文献/章节名较好 | 需 Java 服务；章节 dict **常无 page**；部署重 |

**适用**：OpenChatPaper 主解析；ChatPaper 翻译脚本。

### 3.3 版面 + 阅读序（推荐主路径之一）

| 手段 | 工具/项目 | 优点 | 缺点 |
|---|---|---|---|
| Docling | Paper-Copilot、**本仓库 M1** | 阅读序、page/bbox、表结构、**一次转换可裁图** | 默认 OCR 慢；学术元数据仍弱 |
| MinerU | NeuSym-RAG、SmartPaper 可选 | 复杂版式、公式/图精度高 | GPU/依赖重；偏「转 MD」而非论文产品 |

**适用**：本仓库 ingest 主路径 Docling；难 PDF 可考虑 v1.1 增加 MinerU adapter。

### 3.4 规则版面分块（无 LLM）

| 手段 | 工具/项目 | 优点 | 缺点 |
|---|---|---|---|
| 坐标 + 字号启发式 | pdf-struct-chunker、TreeDex | 轻量、chunk 带 section/page 元数据 | 对版式规范论文效果好，扫描件差 |

**适用**：PyMuPDF 降级、RAG 切块备选。

### 3.5 视觉管线

| 手段 | 工具/项目 | 优点 | 缺点 |
|---|---|---|---|
| 页渲染 + layout 检测 + VLM 读图 | PaperPilot | 架构图理解深 | 成本最高；CLI 为主 |
| 整页/整 PDF VLM | PaperIQ、Docling 可选 enrichment | 免文本抽取 | 难验收步骤↔页码；成本高 |

## 4. 组织层：选什么内容喂给 LLM

### 4.1 M1 — 全文一次生成

**流程**：

```text
PDF → 转全文 markdown/text → 一个 prompt 模板 → 1× LLM → Markdown 报告
```

**代表项目**：[SmartPaper](https://github.com/sanbuphy/SmartPaper)

**优点**：实现最快；易换 YAML 模板、多提供商、流式输出。

**缺点**：

- 上下文超限时长文从尾部截断，**方法细节最先丢**；
- 无章节树、无页码，无法证明「讲的是这篇」；
- 引言容易淹没方法。

**适合**：快速 Demo、短文扫读。**不适合**作为带验收的精读产品主路径。

---

### 4.2 M2 — 整 PDF 多模态直喂

**流程**：

```text
PDF → base64 inlineData → VLM（如 Gemini）→ JSON 卡片 / 自由文本
```

**代表项目**：[PaperIQ](https://github.com/auhonab/PaperIQ)

**优点**：免解析链；读图/公式 natively；产品壳（ELIF 分级、ScholarSight、Chat）完整。

**缺点**：

- 无显式 `Section` / `page` 领域对象；
- 每轮 Chat 重传 PDF，成本高；
- 难以做 quote 子串校验、步骤挂 `figure_id`。

**适合**：黑客松 Demo、按听众讲人话。**不适合**需要「方法步骤 + 原图 + 页码」的精读。

---

### 4.3 M3 — 按论文章节名切段 + 多次调用

**流程**：

```text
PyMuPDF 搜 "Abstract" / "Introduction" / "Method" / "Conclusion"
  → 各段 tiktoken 截断
  → chat_summary → chat_method → chat_conclusion（各 1 次）
  → 固定四问中文 Markdown
```

**代表项目**：[ChatPaper](https://github.com/kaixindelele/ChatPaper)

**优点**：

- **介绍与方法分开生成**（比 M1 合理）；
- 支持 arXiv 关键词批量拉取 + 初筛；
- 四问结构适合「一分钟决定读不读」。

**缺点**：

- 节名**写死英文**（`Approach`、`Proposed Method` 等易匹配失败）；
- 无页码；超长节粗暴截断；
- 提示词 CC BY-NC-ND，不可直接拷贝。

**适合**：arXiv 批量初筛。**可借鉴**：分次调用顺序，不可借鉴：节名匹配方式。

---

### 4.4 M4 — 按输出章节选原文

**流程**：

```text
Docling → heading 树 + 裁图
  → SECTION_MAPPING：每个「输出章」只喂相关「论文章」
  → 每输出章 1× LLM（如 8 次：Overview / Method / Evaluation…）
  → LLM 选图 + 拼 Notion 式 Markdown
```

**代表项目**：[Paper-Copilot](https://github.com/MarcosRodrigoT/Paper-Copilot)

**优点**：

- 解析与讲解分离清晰；
- **PictureItem → PNG + caption**，按节插图；
- 全本地 Ollama，隐私友好。

**缺点**：

- 页码抽了但摘要 prompt **未用**；
- 英文八节自由文本，非独立可刷新的 JSON 对象；
- LLM 选图，非步骤级 `figure_id` 引用。

**适合**：单篇本地笔记。**本仓库借鉴**：Docling 一次转换裁图、按目标选节。

---

### 4.5 M5 — Map-Reduce 切块摘要

**流程**：

```text
pdfminer 全文 → 按段落切块（无页码）
  → 每块 1× LLM（map）
  → 1× LLM 合成（reduce）
  → 固定六节英文合集 Markdown
```

**代表项目**：[paper2md](https://github.com/angelotc/paper2md)

**优点**：

- 模块边界清楚（`pdf_extract` / `summarization` / `cache`）；
- sha256 抽取缓存；`prompts.json` 外置；
- 适合**目录批处理**、给代码库当上下文。

**缺点**：

- 无章节树；块切在纯文本上，**无法点回 PDF 页**；
- 单篇上传精读不是主场景。

**适合**：工程师批量扫论文。**不适合**交互式单篇精读 UI。

---

### 4.6 M6 — 分块笔记 + 多路专题 + 可选 VLM

**流程**：

```text
PyMuPDF 按页 + 切块（带 page/section）
  → 分块 JSON 笔记 + global_overview
  → 视觉子图：layout → crop → VLM 读图
  → 五路并行：background / method / experiments / limitations / key_claims
  → 确定性模板 → 中文 Markdown（brief / standard / detailed）
```

**代表项目**：`refs/PaperPilot-main/`（[PaperPilot](https://github.com/) 类实现）

**优点**：

- 方法分析**最深**；方法节有**字符预算**；
- 输出 JSON + 模板，可测；
- 实验/结论条目可写「第 N 页，章节名」；
- 工程完成度高（LangGraph、pytest、缓存）。

**缺点**：

- 五路 + 视觉子图，**复杂度和成本高**；
- CLI-only；`page` 字段程序**不核对** quote；
- 产物是一大份报告，非「介绍 / 方法」两个独立对象。

**适合**：本机 CLI 图文精读报告。**本仓库借鉴**：方法预算、JSON 输出；**不搬**：五路并行与整套 VLM 子图。

---

### 4.7 M7 — 章节树 + 分路结构化 JSON（本仓库主路径）

**流程**：

```text
ingest：Docling（主）/ PyMuPDF（降）→ Paper + Section[] + Figure[]
  → select_sections(intro)：Abstract / Intro / Conclusion，≤12k 字，可选 1 张总览图
  → select_sections(method)：Method* 节 + 方法图元数据，≤24k 字
  → build_intro：1× LLM → PaperIntro（JSON）
  → build_method：1 或 ≤5× LLM → MethodExplain（JSON，步骤引用 figure_id）
  → 装配：合法 figure_id 挂步骤；未引用图附在 overview 后
  → quote 子串校验 → sourced true/false
```

**代表**：本仓库 [`论文理解-技术方案.md`](论文理解-技术方案.md) 候选 B。

**优点**：

- **总体介绍**与**方法详解**并行、独立刷新；
- 步骤带 `page` + `section_title` + 原图 PNG（非 VLM 手绘）；
- 图以元数据进 prompt，**像素不进文本模型**（成本可控）；
- 与总方案 `Paper` / `Section` / `Figure` 一致，后续实验智能体可复用。

**缺点**：

- 需实现 `select_sections`、分块合成、quote 校验（M2 工作量）；
- 节名启发式 + fallback，极端版式可能 `section_match=fallback`。

**适合**：「5 分钟看懂一篇」+ 带图方法详解 + 可验收引用。

---

### 4.8 M8 — 检索增强问答（RAG）

**流程**：

```text
GROBID / 段落切分 → 扁平段落库
  → 用户提问 → embedding 相似度排序
  → 贪心填入 token 预算 → 改写 system prompt → LLM 回答
```

**代表项目**：[OpenChatPaper](https://github.com/liuyixin-louis/OpenChatPaper)

**优点**：

- **论文内追问**；比全文拼接省 token；
- 章节树 + 段落级检索，形态接近 ChatPDF。

**缺点**：

- 无固定「介绍 + 方法」两块产物；
- 无 quote 门禁；换 PDF 会话管理易出错；
- 需 GROBID 等额外服务。

**适合**：v1.1 问答能力。**可借鉴**：按问选段；**本期不做**（用介绍+方法代替「不知道问什么」）。

**变体 — 章节树选节点（无 embedding）**：[TreeDex](https://github.com/recrudesce/TreeDex) 用 PDF 书签或字体建树，LLM 选相关节点，更轻。

---

### 4.9 M9 — Agentic RAG

**流程**：

```text
PDF 解析 + 元数据 enrichment（DOI、期刊质量…）
  → 向量索引 + 全文检索
  → Agent 多轮：检索 → 阅读 → 再检索（含 citation graph traversal）
  → 带 in-text citation 的回答 / 综述
```

**代表项目**：[PaperQA2](https://github.com/Future-House/paper-qa)

**优点**：

- Scientific QA **SOTA**；引用质量高；
- 支持本地 Ollama / LiteLLM；可处理多篇。

**缺点**：

- 强项是**问答与综述**，不是固定双 Tab UI；
- Agent 循环 LLM 次数多、成本高；
- 与本仓库 M2「确定性管线、不用 tool loop」理念不同。

**适合**：v1.1+ 引用增强、多篇对比。**不宜** fork 为 M2 骨架。

---

### 4.10 M10 — 纯解析（讲解在下游）

只产出结构化文档，不调用讲解 LLM。

| 工具 | 产出 | 典型下游 |
|---|---|---|
| Docling | `DoclingDocument`、Markdown、JSON、裁图 | ingest、RAG、Paper-Copilot |
| scipdf_parser | TEI 章节 dict、参考文献 | GROBID 胶水、OpenChatPaper |
| MinerU | 高精度 Markdown/JSON | Agent 工作流、NeuSym-RAG |

**本仓库**：M1 已实现 ingest → `Paper` / `Section` / `Figure`；M2 在其上建 understand 层。

## 5. 交互形态：报告 vs 讲解 vs 问答

| 形态 | 方法 | 代表 | 用户心智 |
|---|---|---|---|
| **一次报告** | M1–M7 | SmartPaper、ChatPaper、PaperPilot | 上传 → 等报告 → 读完 |
| **按块家教** | M5 变体 + 难度 | [Explainer](https://github.com/rd-serendipity/ai-research-paper-explainer) | 全文摘要 + Chunk 1…N 逐块讲 |
| **对话** | M8、M9 | OpenChatPaper、PaperIQ、Research-QA | 持续提问 |
| **批量雷达** | arXiv API + LLM 筛选 | ChatPaper、arxiv-radar、arxiv_llm_digest | 每日邮件/_digest，非单篇精读 |

## 7. 质量与可验收性

多数开源项目**没有**程序级引用校验。对本仓库精读目标，建议区分：

| 机制 | 含义 | 本仓库 | 常见开源 |
|---|---|---|---|
| **页码字段** | 步骤/条目标注 `page` | ✅ 必填 | PaperPilot 有；多数无 |
| **quote 摘录** | 短英文原文附在论断旁 | ✅ 可选 | 少数 prompt 要求 |
| **sourced 校验** | quote 必须是该页原文子串 | ✅ M2 计划 | **几乎无** |
| **figure_id** | 步骤引用解析出的图，UI 插 PNG | ✅ M2 计划 | Paper-Copilot 近似 |
| **section_match** | 节名匹配失败时暴露 fallback | ✅ | 少数 |

「带图」也要区分：

| 口径 | 说明 | 本仓库验收 |
|---|---|---|
| **版面裁图** | Docling/PyMuPDF 裁 PNG，UI 展示 | ✅ 必须 |
| **VLM 读图** | 模型看像素写讲解 | ❌ 本期不做 |
| **VLM 重画** | 模型生成架构图 | ❌ 不做 |

## 8. 方法选型决策树

```text
你的目标是什么？
│
├─ 批量扫 arXiv，决定读哪篇
│     → M3 ChatPaper 式 或 arXiv digest 工具
│
├─ 目录里几十篇 PDF 变一份合集给工程用
│     → M5 paper2md
│
├─ 单篇快速中文报告，不在乎页码/方法细节
│     → M1 SmartPaper
│
├─ 单篇图文中文 CLI 报告，接受高成本
│     → M6 PaperPilot
│
├─ 上传后 mainly 聊天
│     → M8 OpenChatPaper 或 M9 PaperQA2
│
├─ 不想写解析，Demo 优先
│     → M2 PaperIQ（整 PDF 多模态）
│
└─ 单篇：总体介绍 + 带原图方法详解 + 页码可点 + 可独立刷新
      → M7 本仓库候选 B（Docling ingest + select_sections + 分路 JSON）
```

## 9. 本仓库推荐组合（B+）

不 fork 任一完整仓库，组合如下：

| 层 | 选择 | 借鉴来源 |
|---|---|---|
| 解析 | Docling 主 + PyMuPDF 降 + 题注 clip 兜底 | Docling、Paper-Copilot、本仓库 M1 |
| 组织 | `select_sections(intro \| method)` + 字符预算 | 本仓库方案 + ChatPaper「分次」 |
| 介绍 | 1× LLM → `PaperIntro` | ChatPaper 顺序、SmartPaper 模板外置 |
| 方法 | 直接 1 次或分块 ≤4 + 合成 1 次 → `MethodExplain` | PaperPilot 方法预算 |
| 带图 | 步骤 `figure_ids` + 装配函数 | Paper-Copilot |
| 质量 | quote 子串校验 | **本仓库独有** |
| v1.1 问答 | 章节树选节点 | TreeDex、OpenChatPaper |
| v1.1 难 PDF | MinerU adapter | MinerU |
| v1.1 引用 | in-text citation | PaperQA2 |

**明确不做（本期）**：

- M1 全文一次作为主路径；
- M2 整 PDF 字节给文本/多模态模型；
- M6 五路专题 + 完整 VLM 视觉子图；
- M9 Agent tool loop 驱动 M2 讲解；
- ChatPaper 提示词原文（许可证 ND）。
