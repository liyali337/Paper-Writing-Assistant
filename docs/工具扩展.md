# 工具扩展

对照实现：[`论文检索回答模块.md`](./论文检索回答模块.md)、[`检索回答Agent.md`](./检索回答Agent.md)。  
总方案里更远期的实验闭环见 [`技术方案.md`](./技术方案.md)；Asta 远程 MCP 见 [`Asta-MCP接入指南.md`](./Asta-MCP接入指南.md)。

当前产品 Agent 只读**这一篇**已入库论文。真正挂在 Worker 上的工具只有两把：`search_child_chunks`、`retrieve_parent_chunks`。本文按五类工具体系列出**可扩展**的下一批工具——能接到现有 `KnowledgeService` / HTTP / LangGraph 的优先写；需要新模块或门禁的标为后期。

工具让 Agent 观察环境和采取行动。扩展时先定类型，再写 schema，最后改 Prompt。不要把解析、翻译、问答塞进同一把万能工具。

```text
感知     Agent 主动取信息（检索、读文件、查 API）
执行     Agent 改变世界（写文件、跑命令、调会改状态的 API）
协作     Agent 与子 Agent / 人类分工（委托、确认、协调）
事件     外部输入驱动 Agent 开工（不是 Agent 去调，是环境来推）
沟通     Agent 向用户传递进展与结果（不改论文库，只传信息）
```

前三类是 Agent **主动调用**；事件是 **Environment → Agent** 的观察通道；沟通是 Agent **主动触达用户**，与执行（改外部世界）分开。

## 0. 现状与接入约定

### 0.1 已经落地

| 工具 | 类型 | 落点 | 模型可传 |
|---|---|---|---|
| `search_child_chunks` | 感知 | `understand/agent/tools.py` → `knowledge.query` | `query`，可选 `limit` |
| `retrieve_parent_chunks` | 感知 | 同上 → `get_sections` | `section_id` |

`paper_id` 在 `RetrievalTools` 构造时绑死。第一轮由 `bootstrap_search` 强制搜 Child，禁止凭训练记忆作答。同一 `query` / 同一 `section_id` 不重复调。超 `ASK_MAX_TOOL_CALLS` 走 fallback。

解析、索引、翻译是 HTTP + `BackgroundTasks` 管线，**不是** Agent 工具。intro / method 仍是 M2 占位。Asta MCP 只接到 Cursor 宿主，产品进程里不调用。

### 0.2 加一把「主动调用」工具要改四处

协议是 orchestrator 输出一个 JSON 对象，不是 OpenAI `tools=` native function call：

```json
{"tool":"retrieve_parent_chunks","section_id":"sec-012"}
{"tool":"search_child_chunks","query":"contrastive loss"}
```

| 改哪里 | 做什么 |
|---|---|
| `tools.py` | 实现函数；失败返回稳定哨兵串（如 `NO_RELEVANT_CHUNKS`），不要抛给模型看 traceback |
| `nodes.py` `parse_orchestrator_reply` | 认出新 `tool` 名，抽出参数 |
| `nodes.py` `run_tools` | 去重键、执行、把结构化证据写入 `evidence_bag`（若该工具产出引用） |
| `prompts.py` `orchestrator_prompt` | 何时用、参数从哪来、禁止事项 |

单测对照 `tests/test_ask_agent_tools.py`、`test_ask_agent_worker.py`：工具本身、去重、未知工具名（现为 `UNKNOWN_TOOL`）、熔断。

事件类不走这四处，走 API / 队列 / 定时入口，再 `invoke` 已有图。沟通类改响应通道（HTTP 一次返回、SSE、邮件），一般不进 Worker 工具循环。

### 0.3 统一约束

- 检索类必须能回溯：`section_id` / `page` / `quote`；`quote` 须能在对应 `section.text` 里子串核验。
- 工具给模型的是**观察文本**；给前端的是 `Evidence` / `PaperAnswer`。二者不要混成一段自由散文。
- 高副作用（写库、覆盖译文、改代码）默认拒绝，或先走协作类「请人确认」。
- Skills（`skills/*.md`）是 SOP，注入 Prompt，**不是**工具；不要用 Skill 代替一次检索或一次翻译。
- 外部系统优先 MCP Gateway 再映射为内部同款 schema，业务代码不写死第三方 SDK。本期没有 `mcp_gateway`，新外部能力先本地函数，接口按「将来可换成 MCP」来留。

## 1. 感知工具

让 Agent 访问信息：本地论文结构、索引、译文，以及（后期）外部文献与网络。

当前缺口：只能搜 Child / 取整节，看不到目录、图、译文，也不能出这篇论文。

### 1.1 本篇结构与媒体（优先）

这些都包已有 `KnowledgeService` / `FilePaperStore`，不引入新数据源。

| 工具 | 观察什么 | 建议参数 | 返回要点 | 何时扩展 |
|---|---|---|---|---|
| `list_sections` | 章节树：标题、`kind`、页码、是否有图 | 无，或 `kind` | 短目录，禁止把全文塞进一次结果 | 用户问「方法在哪一节 / 先看什么」 |
| `get_section` | 指定节全文（与 Parent 类似，可带 `kind` 过滤） | `section_id` | 同 `retrieve_parent_chunks`；二选一即可，避免两把同义工具 | 若只想补「按 kind 取第一节」再加 |
| `list_figures` | 本篇或某节的图目录 | 可选 `section_id` | `figure_id`、页、题注；**不**把 PNG 字节喂给文本模型 | 「架构图画的是什么」之前先定位图 |
| `get_figure_caption` | 单图题注 + 所在节摘录 | `figure_id` | 题注原文 + 邻近段落；像素理解留给以后的 VLM，不本期 | 问某张图、或引用要带 `figure_ids` |
| `get_translation` | 某节已生成的中译 | `section_id` | 中文块；未翻译返回哨兵，**不要**在工具里当场开翻（那是执行） | 用户说「中文怎么讲这节」且译文已就绪 |
| `search_captions` | 在题注 / 表注里检索 | `query` | 命中图或表的 locator | 问 Figure 3 / Table 1 对不上正文检索时 |

`retrieve_parent_chunks` 已经覆盖「按 id 取整节」。不要再加一个只改名字的 `read_section`。真正缺的是**目录**和**图题注**。

HTTP 对照（给评测或 UI，不是给模型）：`GET /papers/{id}/sections`、`GET /papers/{id}/figures`、`GET /papers/{id}/translations`。Agent 工具应复用同一函数，避免两套语义。

### 1.2 本篇检索增强（次优先）

| 工具 | 观察什么 | 说明 |
|---|---|---|
| `search_child_chunks` | Child 混合检索 | **已有**。扩展方向：允许 `kind` 过滤（只搜 method / experiment），仍禁止模型传 `paper_id` |
| `retrieve_parent_chunks` | Parent 整节 | **已有**。扩展方向：可选 `max_chars`；一次仍只取一节 |
| `search_by_page` | 某页附近的节/块 | 用户说「第 6 页那个公式」时，正文检索容易漂到摘要 |

跨篇 `search_corpus`（不绑 `paper_id`）**不做**，直到产品有论文库全局搜。串库是一期明确禁止的。

### 1.3 外部文献与网络（后期，走 MCP 或独立适配器）

| 工具 | 观察什么 | 来源建议 | 边界 |
|---|---|---|---|
| `arxiv_search` | 关键词 / arXiv id 元数据 | 总方案 M2 样例 MCP；或本地 HTTP | 返回标题、摘要、id，不替代用户上传的 PDF |
| `asta_paper_search` | Semantic Scholar 语料 | [`Asta-MCP接入指南.md`](./Asta-MCP接入指南.md) | 元数据 + 片段，不是全文下载器 |
| `asta_get_paper` | DOI / arXiv / S2 id 详情 | 同上 | 给「这篇引用了谁」，不给精读正文 |
| `web_search` | 实时网页 | 独立搜索 API | 精读主路径默认**关**；打开时必须和论文内证据分栏，禁止把网页句写成「原文」 |

外部命中**不得**写入 `Evidence.sourced=true`。引用芯片仍只对应本篇 `section.text`。需要外链时另开 `external_refs`，UI 与页码跳转分开。

### 1.4 感知类扩展原则

1. 只读。任何会改 `Paper.status` / 译文 / 索引的动作放到执行类。
2. 模型参数最小化：`query`、`section_id`、`figure_id`、`kind`、`page`。范围由运行时注入。
3. 空结果用哨兵，让 Worker 改写 query 或 fallback，不要让模型把异常当正文。

## 2. 执行工具

让 Agent 改变世界：触发解析、索引、翻译，以及更后期的写代码、跑实验。

当前 Agent **零把**执行工具。管线已存在，缺的是「要不要、在什么门禁下，允许模型去按按钮」。

### 2.1 本仓库已有副作用，可包成工具（须门禁）

| 工具 | 改变什么 | 已有入口 | 建议门禁 |
|---|---|---|---|
| `start_translation` | 为当前论文排队按节翻译 | `POST /papers/{id}/translations` | 用户已点过「中文」或本轮明确说「请翻译」；已在跑则返回状态，不重复开工 |
| `cancel_translation` | 取消进行中的翻译 | `POST /.../translations/cancel` | 仅取消本篇当前 run |
| `rebuild_index` | 强制重建向量索引 | `POST /papers/{id}/index` | 索引 `failed` 或用户要求刷新；`pending` 时拒绝 |
| `reparse_paper` | 重新解析 PDF | `POST /papers/{id}/reparse` | 默认**不要**给问答 Agent；解析失败才由 UI 按钮触发 |

精读问答默认保持只读。把翻译/重建索引进 Worker，会把一次提问变成分钟级任务，和 `ASK_MAX_TOOL_CALLS` 的短循环冲突。更稳的接法：

- 问答 Agent **不**直接执行；
- 沟通层告诉用户「译文未生成，是否开始翻译？」；
- 用户确认后走协作类确认，或仍由前端调现有 HTTP。

若一定要给模型执行权：工具只**投递**后台任务并立刻返回 `run_id` / `status`，不在 tool 调用里阻塞到翻译完成。

### 2.2 总方案中的高风险执行（实验智能体阶段）

未实现，且与当前精读产品分开。落地时必须 `require_human=true`（见总方案 6.5）。

| 工具 | 改变什么 | 模块（规划） |
|---|---|---|
| `fs.read` / `fs.write` | 工作区文件 | `workspace`；写操作根目录绑项目 |
| `git.diff` / `apply_patch` / `rollback` | 代码补丁 | `workspace` |
| `submit_run` / `cancel_run` | 训练或评测任务 | `runner` |
| `shell` | 系统命令 | 默认不暴露给问答模型；仅沙箱 Runner 内部 |

这些**不要**注册进 `understand/agent/tools.py`。问答 Worker 与实验 Graph 分工具白名单，避免精读对话误提交 GPU 任务。

### 2.3 执行类扩展原则

1. 默认拒绝；白名单按 Agent 类型（ask / translate / experiment）分开。
2. 工具返回结构化状态（`queued` / `ready` / `failed`），不返回「我已经翻译好了」这种模型口吻。
3. 幂等：相同请求返回同一 `run_id`，由服务层去重（翻译管线已有类似逻辑）。
4. 禁止在感知循环里同步等待长任务。长任务用事件类「完成后唤醒」。

## 3. 协作工具

让 Agent 与其它 Agent 或人类分工。当前只有图内 `Send` 扇出，最多 3 路 Worker，**没有** HITL，没有跨请求 checkpointer。

### 3.1 图内协作（已有形态，可再拆）

| 机制 | 现状 | 可扩展 |
|---|---|---|
| 子问题 Worker | `rewrite_query` → `Send("worker", …)` | 按题型路由：公式问句只搜 method；「贡献」问句走 intro 口径 Prompt，仍用同一对检索工具 |
| 压缩 / fallback | 超 token 压缩；超预算 fallback | 保持；不要用「再开一个无限 Agent」代替熔断 |
| 聚合 | `aggregate_answers` → `PaperAnswer` | 多路冲突时标 `partial`，不要静默选一路 |

不要把翻译主图、介绍主图和问答主图焊成一张超级图。协作应是**委托一次、收回结构化结果**。

### 3.2 可新增的协作面

| 工具 / 节点 | 和谁协作 | 作用 | 优先级 |
|---|---|---|---|
| `request_clarification` | 人类 | 问题含糊时打断，把澄清问句推给 UI，resume 后再搜 | 教程仓有，本期有意不做；多轮指代失败再开 |
| `ask_user_confirm` | 人类 | 执行类动作前确认（开始翻译、重建索引、改代码） | 任何执行工具进 Agent 之前必须有 |
| `delegate_translate` | 翻译管线 | 问答发现「用户要中文对照」时委托，不等待全文 | 与 2.1 同一门禁 |
| `delegate_intro` / `delegate_method` | 讲解 Agent（M2） | 用户要「讲总体 / 讲方法」时走结构化讲解，而不是用 RAG 硬答长报告 | intro/method HTTP 先实现，再考虑委托 |
| `delegate_research` | 文献子 Agent | 出这篇查引用、找后续工作 | 依赖 1.3 外部感知 |

`request_clarification` 需要 LangGraph `interrupt` + 前端「补充一句再继续」。与现「含糊则原问单路继续搜」不同，会改会话协议，不要偷偷加。

### 3.3 协作类扩展原则

1. 子 Agent 的工具白名单 ⊆ 父任务需要的最小集。问答 Worker 不得继承 `apply_patch`。
2. 人机打断的状态必须可序列化（问题、已检索证据、等待原因）。本期 ask 无 checkpointer，HITL 会倒逼会话存储。
3. 委托返回领域对象（`PaperAnswer`、`Translation`、`Intro`），不要返回另一段 ReAct 对话记录。

## 4. 事件触发工具

与前三类不同：不是 Agent 去调用，而是外部输入把 Agent 拉起来。事件适配器同样是 Environment 提供观察的通道，所以算广义工具。

当前唯一触发器：用户 `POST /papers/{id}/ask`。`BackgroundTasks` 只收尾解析/翻译，**不会**在完成后自动再跑问答图。

### 4.1 可扩展的事件源

| 事件 | 观察 | 唤醒后做什么 | 优先级 |
|---|---|---|---|
| `user_ask` | HTTP 提问 | 现有 ask 图 | 已有 |
| `ingest_ready` | 解析成功 | 自动 `index_paper`（已接近这个：ingest 后可建索引）；可选生成「建议问什么」 | 索引已异步；「建议问题」可后补 |
| `index_ready` | 向量索引就绪 | 通知前端解除提问禁用；不要自动编造一篇综述 | 沟通类更合适 |
| `translation_done` | 某篇/某节译完 | 可选：对用户上次问过、因无中译而失败的问题重答 | 低；需会话记忆 |
| `schedule_digest` | 定时（如每日 06:00） | 总方案 `research.harvest` → 今日简报 | 实验/雷达阶段 |
| `webhook_arxiv` | 外部系统回调 | 新论文元数据入库或提醒 | 需鉴权；精读产品非必需 |
| `email_inbound` | 新邮件 | 把附件 PDF ingest，或把邮件正文当 `ask` | 产品形态变化大，靠后 |

事件适配器应只做三件事：验签 / 鉴权、映射成领域对象（`paper_id`、`question`、`run_id`）、调用已有服务。**不要**在 webhook 处理函数里直接 `harness.chat`。

### 4.2 事件类扩展原则

1. 事件入口与工具循环隔离。入口代码不得出现 `{"tool": ...}` 解析。
2. 同一事件要幂等（重复 webhook 不重复 ingest）。
3. 长任务完成用「状态变更事件」驱动沟通（「索引好了」），不要让 Worker 轮询 `index_status`。

## 5. 用户沟通工具

Agent 主动与用户传信息。和执行不同：不改论文库，只改用户看到的内容与通道。

当前：一次 HTTP 返回 `PaperAnswer`（`answer_zh` + 引用芯片）。无流式、无推送、无邮件。翻译进度靠前端轮询 `GET /translations`。

### 5.1 可扩展通道

| 工具 / 通道 | 传递什么 | 落点建议 | 优先级 |
|---|---|---|---|
| `reply_answer` | 最终中文回答 + 引用 | 已有 `PaperAnswer` | 已有（被动响应，不是模型调的 tool） |
| `stream_tokens` | 生成中的 token / 节点名 | SSE 或 WebSocket；先推「正在检索 / 正在聚合」，再推答案 | 体感优先于新感知工具 |
| `post_citation` | 可点击的节名·页码 | 现有芯片 + `onJump`；沟通层不要改成模型输出 `Sources: foo.pdf` | 保持程序装配引用 |
| `notify_progress` | 索引中、翻译中、失败原因 | 现有 status 芯片；可升为 SSE `index_pending` | 与事件 `index_ready` 成对 |
| `suggest_questions` | 读完目录后的 3 个可点问句 | 解析或索引完成后生成，写入 UI 空态 | 冷启动 |
| `notify_email` / `notify_im` | 简报、长任务完成 | 事件驱动后发送 | 雷达 / 实验阶段 |

不要把「给用户发消息」注册成 Worker 的 `{"tool":"send_email"}`，除非那是实验 Agent 的专职通道。精读问答里，沟通是 **API 响应形态**，由服务在 `collect_answer` / `aggregate_answers` 之后装配。

### 5.2 沟通过程中的观察（可选，仍属沟通而非感知）

若做教程那种折叠时间线，可向 UI 推：

- 改写后的子问题列表
- 调用了哪把工具（名称即可，不必把 Child 全文给用户）
- fallback / `partial` / `no_evidence` 原因

这是可开关的调试面，默认产品 UI 可以忽略（设计文档已允许）。

### 5.3 沟通类扩展原则

1. 引用由程序映射，模型只出 `[n]` 或纯中文；页码跳转不交给模型「选文件」。
2. `no_evidence` 必须说没有，沟通层不得改写成肯定句。
3. 流式只增通道，不改 `PaperAnswer` 字段契约；断流时仍能用非流式结果。

## 6. 建议接入顺序

按「不破坏只读精读、能复用现有服务、改动面小」排序。

| 批次 | 类型 | 做什么 | 不做什么 |
|---|---|---|---|
| A | 感知 | `list_sections`、`list_figures` / `get_figure_caption` | 跨篇、联网 |
| B | 沟通 | ask 过程 SSE 或节点进度；空态建议问句 | 邮件、IM |
| C | 感知 | `search_child_chunks` 增加可选 `kind`；`get_translation`（只读已有译文） | 工具内开翻 |
| D | 协作 + 执行 | `ask_user_confirm` + `start_translation` 投递 | 问答循环里阻塞翻译 |
| E | 事件 | `index_ready` / `translation_done` 通知前端 | webhook 直接调 LLM |
| F | 感知（外部） | arXiv 或 Asta，命中进 `external_refs` | 当成本篇 `Evidence` |
| G | 执行 + 协作 | 工作区补丁、Runner、HITL 实验门禁 | 注册进问答 Worker |

A–C 仍在「当前这篇论文」产品切片内。F–G 才进入总方案的文献雷达与实验闭环。

## 7. 类型对照（扩完之后应仍能一眼看懂）

```text
感知     list_sections / 现有检索 / 图题注 / 只读译文 / （后）Asta·arXiv
执行     （后）投递翻译与重建索引；实验阶段才有 patch / run / shell
协作     现有 3 路 Worker；（后）澄清、确认、委托讲解或翻译
事件     现有 user_ask；（后）index_ready、定时简报、webhook
沟通     现有 PaperAnswer；（后）SSE 进度、建议问句、长任务通知
```

扩展合格的标准不是工具数量，而是：**问答主路径仍然先搜再答、引用可跳页、高副作用必须经过确认、事件只负责叫醒已有图。**
