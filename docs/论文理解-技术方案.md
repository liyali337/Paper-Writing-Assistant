# 论文理解 技术方案

本文是仓库第一期可交付能力的实施方案，承接总方案 `docs/技术方案.md` 中的 `knowledge` / `harness`，**不实现**实验改代码、训练提交、每日论文雷达、论文内追问、学者库对齐。

用户价值：上传一篇论文 PDF 后，系统先按标题把正文和图拆开，再给出两块中文材料——**总体介绍**（这篇在解决什么、贡献是什么）和**方法详解**（它怎么做、步骤旁带原图）——用来快速看懂一篇论文。

成功标准：

- 用户上传一篇可复制文本的 PDF，先看到按标题展开的章节树，每节可列出该节抽出的图。
- 5 分钟内看到「总体介绍」和「方法详解」两块中文分析；方法详解中出现的架构图/流程图是从 PDF 裁出的原图，不是模型手绘。
- 介绍能独立回答：问题、动机、贡献、任务设定；方法能独立回答：流水线步骤、关键模块、相对旧方案改了什么，且步骤能挂上对应图号。
- 方法步骤能点回原文章节名与页码；解析失败（扫描件、加密、空文本）必须显式失败，不得生成假报告。
- 同一份 PDF 重复上传不重复解析；同一解析结果可按 prompt 版本刷新分析。

开源参考在 `refs/`（总览 `refs/功能介绍.md`，各库对照 `refs/*技术方案介绍.md`）。本期只借鉴其**已验证的链路形态**，不 fork 任何一条仓库当产品骨架。对照见附录 A。

## 1. 背景与目标

仓库 `Paper-Writing-Assistant` 当前无业务代码，仅有总方案、Asta 接入说明、MCP 示例配置，以及 11 份开源参考实现。总方案把 PDF 入库定义为 `knowledge.ingest()` / `knowledge.query()`，但未规定「帮人快速看懂一篇论文」的产品形态。

现有参考实现各自只覆盖半段：

| 缺口 | 参考里怎么做 | 对本期的含义 |
|---|---|---|
| 解析有结构、无讲解 | Docling / scipdf_parser | 解析必须出章节树，但不能停在 Markdown 导出 |
| 一次转换同时出图 | Paper-Copilot：`generate_picture_images=True` | ingest 必须同时产出 `Section` 与 `Figure`，按阅读序挂到当前标题 |
| 讲解有中文、无结构输入 | SmartPaper 全文一次；ChatPaper 按英文节名三次 | 必须先按标题分解再分节喂模型，介绍与方法分开生成 |
| 方法讲得细、产品过重 | PaperPilot 五路专题 + VLM 读图 + CLI | 保留「方法单独一条、有字符预算」；抽图用 Docling 裁剪，不搬整套视觉子图 |
| 能追问、冷启动差 | OpenChatPaper / Research-QA | 本期不做问答；用介绍+带图方法代替「不知道问什么」 |

本需求要把这条能力做成独立可用的产品切片：

| 输入 | 输出 |
|---|---|
| 论文 PDF | 按标题切开的章节树 + 每节挂上的原图 PNG |
| 同一份解析结果 | 中文「总体介绍」结构化对象（可钉 1 张总览图） |
| 同一份解析结果 | 中文「方法详解」结构化对象（步骤旁插入该节原图） |

目标不是「再生成一篇摘要」，也不是「对着论文聊天」。目标是：先按标题把论文拆开（含图），再建立地图（总体介绍），再把方法连图讲清楚。

## 2. 范围与非目标

### 2.1 范围（In Scope）

- 单篇 PDF 上传、校验、私有存储；按内容哈希去重。
- **按标题分解**：阅读序遍历 → heading 开新 `Section`；正文、题注归入当前节；切分后带 `paper_id / page / section`。
- **按图分解**：同一份解析产物裁出插图 PNG，绑定 `section_id` + 页码 + 题注；过小图标过滤。
- **总体介绍**（中文）：一句话、问题、动机、贡献列表、任务/数据设定、建议阅读顺序；可钉 1 张总览/架构图。
- **方法详解**（中文、带图）：方法总览、分步流水线、关键模块、与旧方案的差异、方法侧假设与局限；方法节内的图插入对应步骤（模型未对齐时按题注顺序附在总览后）。
- 方法步骤标注原文 `section` + `page`；关键论断尽量带短摘录（程序做子串校验，校验失败则丢弃该条摘录，保留中文讲解并标 `unsourced`）。
- FastAPI + React 最小产品壳：上传、轮询状态、章节树（含缩略图）、总体介绍、带图方法详解。
- 审计：每次生成记录所用模型、token、prompt 版本、引用丢弃数、抽图数量。

### 2.2 非目标（Out of Scope，本期不做）

- 不做论文内问答 / RAG 对话框（OpenChatPaper 形态放到 v1.1）。
- 不做 Asta / Semantic Scholar 元数据对齐。
- 不写实验代码、不跑训练、不改用户仓库（总方案 M3 以后）。
- 不做多篇对比综述、不做自动投稿、不做 arXiv 关键词拉取（ChatPaper 主路径）。
- 不做扫描件 OCR 主路径；扫描 PDF 标 `needs_ocr`，提示换可复制文本的 PDF。
- 不搬 PaperPilot 整套 VLM 视觉子图（页级 layout 检测、裁剪质量打分、选关键图模型）。抽图是版面裁剪，不是像素级「看懂这张图」。
- 不承诺矢量线稿架构图 100% 抽到（Docling `PictureItem` 抽不到纯 path 绘图时，用题注邻域整块 clip 兜底，失败则该图缺位、方法文本仍出）。
- 不在本期引入独立用户体系、向量库、embedding；单机/单租户，检索用章节规则即可。
- 不拷贝 ChatPaper 提示词原文（CC BY-NC-ND）；只对照其「摘要 / 方法 / 结论分次调用」的顺序。

## 3. 现状与主要痛点

### 3.1 现状

- 无模块、无接口、无存储 schema、无 CI。
- 可复用约定已在总方案落定：Python 3.11+、FastAPI、PostgreSQL、对象存储、OpenAI 兼容 LLM、MCP Gateway（本期不用）。
- 仓库 `refs/` 内已有可对照的解析器与讲解管线源码：`docling-main/`、`scipdf_parser-master/`、`PaperPilot-main/`、`Paper-Copilot-main/`、`SmartPaper-main/`、`ChatPaper-main/` 等。
- Asta 已在本机 Cursor 配好，但**本期不调用**：它给元数据与约 500 词片段，不能替代用户上传的那一版全文，也不服务「介绍 + 方法」主路径。

### 3.2 痛点（若直接套某一份开源）

- **SmartPaper / PaperIQ**：整篇一次进模型。长文截断、方法细节被引言淹没，无法验收「讲的是这篇」。
- **ChatPaper**：按写死英文节名切三段，算法论文叫 `Approach` 时方法节可能空；无页码；许可证不能演绎。
- **Paper-Copilot**：Docling 章节可用，但产出是英文八节自由文本，页码抽了不用。
- **PaperPilot**：中文方法分析最接近需求，但五路并行 + 读图 + 本地记忆过重，且 `page` 字段程序不核对原文。
- **scipdf_parser**：GROBID 章节/作者好，对外 dict **没有页码**，还要本机 Java 服务。
- **Docling 默认配置**：默开 OCR，可复制论文也会又慢又占 GPU；学术题名/作者仍是 Coming soon。
- **与总方案脱节**：若另起一套「总结脚本」，后续实验智能体无法复用同一 `Paper` / `Section`。

## 4. 方案候选对比（2-3个）

### 候选 A：全文抽取 + 一次 LLM 出介绍和方法

- **核心思路**：对标 SmartPaper。PyPDF/MarkItDown 抽全文，一个提示词同时写「介绍」和「方法」。
- **影响模块**：一个上传接口 + 一个 prompt。
- **数据/接口变化**：只有 `markdown: str`，无章节对象，无页码。
- **风险与成本**：实现最快；10 页以上方法被截断；无法证明方法步骤来自原文；后续无法复用 `knowledge`。
- **适用边界**：海报 Demo。不适合作为本仓库第一期能力。

### 候选 B：按标题+图分解，再分路生成总体介绍与带图方法详解（推荐）

- **核心思路**：一次 Docling 转换同时得到 heading 树和裁图 → 图按阅读序挂到当前标题 → 总体介绍只吃 Abstract + Introduction + Conclusion → 方法只吃 Method 类章节及其挂图 → 文本 LLM 出 JSON（步骤引用 `figure_id`）→ UI 把 PNG 插进对应步骤。
- **影响模块**：在总方案上只新增 `understand`；`knowledge.ingest()` 产出 `Paper + Section[] + Figure[]`；本期不实现向量检索。
- **数据/接口变化**：领域对象增加 `Figure`；HTTP 增加 figures 资源；intro / method 可引用 `figure_id`。
- **风险与成本**：中等。抽图与标题绑定要做过滤（logo、页眉图标）；矢量架构图需 clip 兜底。LLM 调用次数与无图方案相同（图以元数据进 prompt，像素不进文本模型）。
- **适用边界**：第一期就要「按标题拆开、方法带原图、快速看懂」。

### 候选 C：PaperPilot 式全图（分块笔记 + 五路专题 + VLM 读图）

- **核心思路**：对标 PaperPilot。切块笔记 → 全局地图 → 背景/方法/实验/局限/结论并行 → VLM 检测框/打分/读图 → 模板拼报告。
- **影响模块**：几乎整张 LangGraph；还要视觉子图、缓存、三种密度模板。
- **数据/接口变化**：产物是一份大 Markdown，不是两个可独立刷新的对象。
- **风险与成本**：高。本期用户要的是标题分解 + 带图方法，不是实验专题和像素级读图；VLM 失败链可作 v1.1，整图不必搬。
- **适用边界**：已经要出可打印精读报告、且接受 CLI / 视觉模型的阶段。

## 5. 推荐方案与取舍理由

采用**候选 B**。

不是 A：一次 prompt 无法保证方法细节，也没有章节树和图文件可复用。  
不是 C：VLM 读图和五路专题超过「按标题拆开 + 带图方法详解」的交付面。  
选 B 的深模块理由：对外只有 `ingest_pdf`、`get_intro`、`get_method` 三个动作（figures 是 ingest 的附属资源）；解析、抽图、节选、预算、JSON 校验、图-步骤对齐全藏在内部。介绍与方法可独立重生成，图不重复裁。

本期「带图」的验收口径（已锁定，避免和 VLM 读图混淆）：

| 必须做到 | 明确不做（本期） |
|---|---|
| PDF 按 heading 切成 `Section` | 模型自己决定切哪里 |
| 插图裁成 PNG，挂到所属节 | 把整页 PDF 字节丢给多模态模型 |
| 方法详解页面展示原图 + 题注中译 | 用 VLM 把架构图「翻译」成逐步动画 |
| 步骤 JSON 引用 `figure_id`，对不上则按节附在总览后 | 抽不到图就中断方法文本 |

概念落点（与总方案一致，禁止再造同义词层）：

| 概念 | 落点 | 本期用法 |
|---|---|---|
| Prompt | `harness.prompts` | `build_intro` / `note_method_chunk` / `synthesize_method` |
| Function Call | 主路径**不用** tool loop | 生成是确定性管线，不让模型自己搜网或选工具 |
| Tool / MCP | `mcp_gateway` | 本期不调用 |
| Skills | `skills/paper-explain.md` | 规定介绍口径、方法口径、禁止编造模块名与数字 |
| RAG | `knowledge` | 本期不做向量检索；节选靠标题启发式 + 长度预算 |
| Harness | `harness` | LLM 调用、JSON 校验、预算、审计 |
| LangChain | `knowledge.adapters` | 仅作 splitter 备选；主解析走 Docling 适配器 |
| LangGraph | 可用可不用 | 若用，只跑 `ingest → intro → method` 三节点；不做实验图 |

已自动确定（空仓库 + 总方案 + 开源对照，不向用户再确认）：

- 讲解语言：中文；术语、模型名、数据集名、公式符号：保留英文原文。
- 单租户本地优先；对象存储先用本地目录，接口按 S3 key 设计。
- LLM：OpenAI 兼容 `base_url` + `api_key`。
- 元数据：PostgreSQL。本期不上 Qdrant。
- 解析主路径：Docling，**显式关闭 OCR**，**开启** `generate_picture_images=True`（建议 `images_scale=2.0`），设 `document_timeout`；失败或文本过少再标 `needs_ocr`，不自动硬转。
- 解析降级：Docling 超时/崩溃 → PyMuPDF 按页 `sort=True` 抽字 + 标题启发式，并用 xref / 题注邻域 clip 抽图，状态记 `parser=pymupdf`。
- GROBID / scipdf：**不进主路径**（要 Java 服务、章节无 page、pdffigures2 jar 本快照缺失）。
- 上传成功后**自动**生成总体介绍与方法详解；二者并行，都只依赖解析（含图），互不依赖。
- 文本 LLM 只看图的 `label/caption/page/section`，不看像素；无 `VISION_*` 时方法仍然带图展示。

## 6. 详细设计

### 6.1 模块与职责（含接口边界）

```text
UI / CLI
    │
    ▼
api.papers          薄 HTTP，不写解析逻辑
    │
    ├─ knowledge.ingest(pdf) → Paper          # 内含 sections + figures
    ├─ knowledge.get_sections(paper_id) → list[Section]
    ├─ knowledge.get_figures(paper_id, section_id?) → list[Figure]
    ├─ understand.build_intro(paper_id) → PaperIntro
    └─ understand.build_method(paper_id) → MethodExplain
            │
            └─ harness.complete(schema)
```

| 模块 | 职责 | 对外接口 | 不该做的事 |
|---|---|---|---|
| `api` | 上传、轮询、取章节/图/介绍/方法 | REST | 拼 prompt、切 PDF、裁图 |
| `knowledge` | 存 PDF、按标题切节、裁图、绑定节 | `ingest()`, `get_paper()`, `get_sections()`, `get_figures()`, `select_sections()` | 写中文讲解、选哪张图「好看」 |
| `understand` | 合成 `PaperIntro` / `MethodExplain`，步骤引用已有 `figure_id` | `build_intro()`, `build_method()` | 再解析 PDF、把像素塞进文本模型 |
| `harness` | 模型调用、JSON schema 校验、重试、token 预算、审计 | `complete()` | 业务对象生命周期 |
| `skills` | 讲解 SOP | `render("paper-explain")` | 副作用 |

解析器选型（藏在 `knowledge.adapters.pdf`，调用方只看见 `ParsedPaper`）：

1. **主路径 Docling**：`PdfPipelineOptions(do_ocr=False, do_table_structure=True, generate_picture_images=True)`，`images_scale=2.0`，`document_timeout` 必填（建议 120s）。一次 `convert` 同时服务章节和图，禁止为抽图再转一遍。
2. **按标题切节**：按阅读序 `iterate_items()`；遇到 heading 开启新 `Section`（记录 `level`、`page_start`）；后续段落、表格文本、题注写入当前节，直到下一个同级或更高级 heading。运行标题、页码、纯 `Acknowledgements` 过滤掉。
3. **按图切出**：每个 `PictureItem` 若有 image 则落盘 PNG。绑定规则：阅读序上「属于当前未关闭的 Section」。题注优先 `caption_text`；否则同页匹配 `^(fig(?:ure)?|table)\s*\.?\s*\d+`（Paper-Copilot 回退）。过滤：宽或高 < 80px、面积过小的 logo/icon 丢弃。`TableItem` 不另存图，表格结构进所属节的 `text`（Markdown）。
4. **矢量图兜底**：无 `PictureItem` 但该页有 `Figure N` 题注 → 用题注 bbox 上方一块区域 `page.get_pixmap(clip=...)` 裁（PyMuPDF），`source=page_clip`。仍失败则只保留题注记录、`storage_key=null`，不阻断 ingest。
5. **降级 PyMuPDF**：按页文本 + `sort=True` + 标题启发式；图用 `page.get_images` 或题注 clip。无栏坐标时接受双栏错序，UI 提示 `parser=pymupdf`。
6. **失败**：平均每页 < 200 字符，或全文 < 800 字符 → `needs_ocr`，不生成介绍/方法。
7. **附录裁剪**：默认在 `References` / `Bibliography` / `参考文献` 之后截断附录；其后的图不再入库。

节选规则（`knowledge.select_sections`，规则引擎，不调模型）：

| 产物 | 纳入文本 | 纳入图 | 排除 | 预算 |
|---|---|---|---|---|
| 总体介绍 | Abstract；`intro`/`background`/`motivation`；Conclusion / 贡献段 | 至多 1 张：caption 含 architecture/overview/framework，否则方法节第一张 | Method 细节、Related Work 全文、References | 文本 ≤ 12_000 字符 |
| 方法详解 | `method`/`approach`/`model`/`architecture`/`proposed`/`framework` 及其子节 | 这些节上 `storage_key` 非空的全部 Figure（默认上限 12 张，超出按面积从大到小） | 纯 Experiments 结果图（柱状图/消融表图）默认不进方法，除非 caption 含 architecture/pipeline | 文本 ≤ 24_000 字符；图只传元数据进 LLM |

匹配大小写不敏感，允许 `3. Method`、`III. OUR APPROACH`。一篇里一个都匹配不到：介绍退回前 4 页 + Abstract；方法取最长非 intro/related/ref 章节，并标 `section_match=fallback`。

### 6.2 关键流程与异常路径

#### 6.2.1 上传与入库

```text
POST /papers
  → 校验 MIME / 扩展名 / 大小（默认 ≤ 50MB）
  → 计算 sha256，命中则返回已有 paper_id（同文件不重复解析、不重裁图）
  → 写入对象存储 papers/{paper_id}/source.pdf
  → 任务状态 queued
  → worker:
        parse headings → sections
        crop pictures → figures（挂 section_id）
        status=ready
        并行 enqueue: build_intro, build_method
        失败 → status=ingest_failed | needs_ocr，保留错误码
  → UI 轮询 GET /papers/{id}；ready 后可先展示章节树+缩略图，再等 intro/method
```

同步上限：≤ 20 页可在 `POST /papers` 等到 `ready`（超时 90s 则改轮询；开抽图后比纯文本略慢）。UI 一律按任务轮询。

异常：

| 条件 | 处理 |
|---|---|
| 非 PDF / 加密无法打开 | `400 invalid_pdf` |
| 扫描件文本过少 | `needs_ocr`，UI 说明原因，不调用 LLM |
| Docling 超时 | 记 warning，自动降级 PyMuPDF；两者都失败 → `ingest_failed` |
| 抽到 0 张图 | ingest 仍 `ready`，`figure_count=0`；方法文本照出，UI 提示「未抽出插图」 |
| 介绍成功、方法失败 | `intro_ready` + `method_failed`，允许只重试方法 |
| LLM JSON 非法 | 同节重试 1 次；仍失败该产物 `failed`，不污染另一产物 |

#### 6.2.2 总体介绍生成

输入：`select_sections(kind=intro)` 的原文 + 可选 1 张总览图的 `{figure_id, label, caption, page}`。禁止塞方法细节全文，禁止把 PNG 字节发给文本模型。

一次 `harness.complete(PaperIntro)`。Skill 硬约束：

- 不把通用领域知识写成「本文证明了…」。
- 贡献必须能在输入章节中找到对应表述；找不到就少写，不补三条凑数。
- 数据集、指标、SOTA 数字没有出现在输入里，就写「介绍所用章节未给出」，不要用训练记忆补。
- `overview_figure_id` 必须是传入目录中的 id，否则置空。

#### 6.2.3 方法详解生成（带图）

禁止「把全文或整本 Method 一次性交给模型出一篇散文」。图不参与分块像素，只作为目录：

```text
method_secs = select_sections(kind=method)
method_figs = figures of those sections, cap 12

if concat(method_secs) ≤ METHOD_DIRECT_LIMIT:      # 默认 16_000
      1 次 complete(MethodExplain)  # 输入：节文本 + 图目录
else:
      按 8_000 字符切块
      每块 1 次 complete(MethodChunkNote)           # 最多 4 块
      1 次 complete(MethodExplain) 只吃笔记 + 图目录
```

装配（纯函数，不再调 LLM）：

1. 若步骤的 `figure_ids` 落在 `method_figs` 内 → 该步下方插图。
2. 未被任何步骤引用、但仍属方法节的图 → 按 `label` 顺序附在 `overview_zh` 之后（保证「方法详解一定带图」，只要解析出了图）。
3. 引用了不存在的 `figure_id` → 丢弃该引用，打 warning。

单篇方法最多 1 + 4 次 LLM。超预算返回已完成笔记合成结果 + `partial=true`。

Skill 硬约束：

- 步骤顺序按原文，不把 Experiments 的训练技巧说成模型结构。
- 模块名、损失名、符号以原文为准；讲解用中文说「这个模块干什么」。
- 公式用原文能抄到的 LaTeX/Unicode；抄不到就描述含义，不发明符号。
- 讲架构时优先引用 `Figure N` 对应的 `figure_id`，不要用文字「想象一张图」。
- 每条 `pipeline_steps` 必须带 `section` + `page`；`quote` 若无法在该页规范化文本中子串匹配，则清空 quote、`sourced=false`，**不丢弃**中文步骤。

引用核验：空白规范化后，`quote` 必须是对应 `page` 原文的子串，或 0.9 重叠的滑动窗口。失败只影响该条 `sourced`。

#### 6.2.4 停止与预算

- 介绍：1 次 LLM。
- 方法：1 或 ≤5 次 LLM。
- 抽图：无额外 LLM。
- 用户取消：worker 停，PDF、sections、已裁 PNG 保留；已完成的 intro/method 保留。

### 6.3 接口与数据契约

#### 6.3.1 领域对象

```python
class Paper:
    paper_id: str
    sha256: str
    filename: str
    status: str          # queued|parsing|ready|needs_ocr|ingest_failed
    parser: str          # docling|pymupdf
    page_count: int
    figure_count: int
    title: str | None    # 解析启发式或首页大字号，允许空
    authors: list[str]
    abstract: str | None
    language: str        # 告警用，不拒绝非英文
    intro_status: str    # pending|ready|failed|skipped
    method_status: str   # pending|ready|failed|skipped|partial

class Section:
    section_id: str
    paper_id: str
    title: str           # 原文
    kind: str            # abstract|intro|related|method|experiment|conclusion|references|other
    level: int
    page_start: int
    page_end: int
    text: str
    parent_id: str | None
    figure_ids: list[str]

class Figure:
    figure_id: str
    paper_id: str
    section_id: str | None
    page: int
    kind: str            # figure|table_snapshot|algorithm
    label: str | None    # 如 Figure 3
    caption: str | None  # 英文题注
    storage_key: str | None  # papers/{id}/figures/{figure_id}.png；clip 失败可空
    source: str          # docling_picture|pymupdf_xref|page_clip
    width_px: int
    height_px: int
    bbox: tuple[float, float, float, float] | None

class Evidence:
    page: int
    section_title: str | None
    quote: str           # 英文短摘录，建议 ≤ 40 词
    sourced: bool        # 子串核验是否通过

class PaperIntro:
    paper_id: str
    title_zh: str
    one_sentence_zh: str
    problem_zh: str
    motivation_zh: str
    contributions: list[str]
    task_setting_zh: str          # 任务、数据、评测设定（有则写）
    reading_order_zh: list[str]   # 建议先看哪些节
    overview_figure_id: str | None
    evidence: list[Evidence]      # 支撑贡献/问题的摘录，可空
    partial: bool
    section_match: str            # matched|fallback
    model: str
    prompt_version: str

class MethodStep:
    name: str                     # 可用英文模块名
    what_zh: str
    page: int
    section_title: str
    quote: str | None
    sourced: bool
    figure_ids: list[str]

class MethodExplain:
    paper_id: str
    overview_zh: str
    pipeline_steps: list[MethodStep]
    key_modules: list[MethodStep]
    vs_prior_zh: str              # 相对旧方案改了什么
    assumptions_zh: list[str]     # 方法侧假设/适用范围
    open_to_read_zh: list[str]    # 建议对照原文的公式/算法编号
    figure_ids: list[str]         # 本篇方法实际展示的图（含未挂到步骤的）
    partial: bool
    section_match: str
    model: str
    prompt_version: str
```

`select_sections` 返回 `list[Section]`，禁止返回无 `page_start` 的自由文本。`get_figures` 必须能按 `section_id` 过滤。

#### 6.3.2 HTTP

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/papers` | `multipart/form-data` 上传 PDF，返回 `paper_id` + `status` |
| GET | `/papers/{id}` | 元数据、解析状态、intro/method 状态、`figure_count` |
| GET | `/papers/{id}/sections` | 章节树（含每节 `figure_ids`） |
| GET | `/papers/{id}/figures` | 图清单；`?section_id=` 过滤 |
| GET | `/papers/{id}/figures/{fid}` | PNG 字节（`storage_key` 为空则 404） |
| GET | `/papers/{id}/intro` | 最新总体介绍；未就绪 202 + `status` |
| POST | `/papers/{id}/intro` | `?refresh=true` 重生成 |
| GET | `/papers/{id}/method` | 最新方法详解（含 `figure_ids`）；未就绪 202 |
| POST | `/papers/{id}/method` | `?refresh=true` 重生成 |

不提供 `/ask`、`/enrich`、`/brief`。刷新 intro/method **不重裁图**。

#### 6.3.3 Prompt 装配

介绍：

```text
[System = paper-explain skill / intro]
[Instruction = 只根据下列章节输出 JSON；overview_figure_id 必须来自图目录]
[Sections: title, page_start-page_end, text]
[Figures: figure_id, label, caption, page, section_title]
```

方法（直接路径）：

```text
[System = paper-explain skill / method]
[Instruction = 按原文顺序拆解；步骤用 figure_ids 引用下图目录中的 id]
[Sections …]
[Figures: figure_id, label, caption, page, section_title]
```

方法（长文合成）：

```text
[System = 同上]
[MethodChunkNote JSON 列表]
[图目录，无 PNG]
```

输出一律 JSON schema；解析失败重试 1 次。PNG 永不进入这些 prompt。

### 6.4 存储与迁移策略

无历史数据。表：

- `papers`：元数据、状态、sha256 唯一、`parser`、`figure_count`。
- `sections`：解析产物；重新 ingest 时按 `paper_id` 覆盖。
- `figures`：图元数据；文件在对象存储，库里只存 key。
- `paper_intros`：`paper_id` + `prompt_version` + `model`；刷新插入新行，GET 取最新。
- `method_explains`：同上，与 intro 分表，便于只重跑方法。
- `audit_logs`：`trace_id, paper_id, stage, model, tokens, latency_ms, sourced_drop_count, figure_count`。

对象存储：`papers/{paper_id}/source.pdf`，`papers/{paper_id}/figures/{figure_id}.png`。解析中间结果可选落 `papers/{paper_id}/parsed.json`。重新 ingest 同一 `paper_id` 时先删旧 figures 再写。

不上 Qdrant。embedding 模型变更与本期无关。

### 6.5 安全、权限与脱敏

- PDF 仅本地私有库；本期不向任何外部学术 API 发送标题或全文。
- 密钥：`OPENAI_API_KEY` 只走环境变量；禁止进 prompt、日志、仓库。
- 上传类型白名单：`application/pdf`；检查 `%PDF` 头。
- 路径：对象键由服务端生成 UUID，不用用户文件名当路径。
- 日志：不打印 section 全文（可打 hash + 前 80 字符）；不打印 API key。
- 版权：产品定位为用户对自己有权使用的 PDF 做私人阅读辅助，不做论文分发。
- ChatPaper 许可：实现时禁止粘贴其仓库内提示词与打分表原文。

### 6.6 可观测性（日志/指标/追踪）

必带字段：`trace_id`, `paper_id`, `stage`（ingest|parse|intro|method）。

日志点：

- ingest：页数、字符数、section 数、figure 数（含 `source` 分布）、`parser`、是否 `needs_ocr`。
- intro / method：输入字符数、LLM 次数、`section_match`、`sourced=false` 条数、引用的 figure 数、`partial`。

指标：

- `pdf_ingest_seconds{status,parser}`
- `pdf_parse_chars_per_page`
- `pdf_figures_extracted{source}`
- `explain_unsourced_ratio`
- `method_figure_attach_ratio`（方法页实际插入图 / 方法节抽出图）
- `method_partial_total`
- `llm_calls_per_paper`

追踪：每篇 paper 一条 root span；parse / intro / method（及每块笔记）为子 span。

## 7. 风险、依赖与回滚

| 风险 | 影响 | 缓解 | 回滚 / 兜底 |
|---|---|---|---|
| 双栏/页眉污染 | 方法步骤错序 | Docling 阅读序；过滤重复页眉；PyMuPDF 降级时 UI 提示 | 侧栏展示该节原文 |
| 节名匹配失败 | 方法吃到引言 | fallback + `section_match` 暴露；允许 refresh | 用户仍可读 sections |
| 模型用记忆而非 PDF | 讲成另一篇 Transformer | 分节限上下文 + quote 核验 + Skill 禁补数字 | 只展示章节树与原文 |
| 方法节过长 | 截断关键模块 | 分块笔记上限 4；`partial=true` | `POST /method?refresh=true` |
| Docling 默开 OCR / 超时 | worker 卡死、GPU 争用 | 强制 `do_ocr=False` + timeout；解析进程与 API 进程隔离 | 降级 PyMuPDF |
| Docling 无作者题名 | 侧栏标题像文件名 | 首页启发式 + Abstract 首句；允许 `title=null` | 显示 filename |
| 抽图 0 张 / 矢量架构图 | 方法无图 | logo 过滤阈值可调；题注邻域 clip 兜底 | 方法文本仍出；UI 标「未抽出插图」 |
| 图挂错节 | 实验图进方法 | 阅读序绑定 + Experiments caption 默认剔除 | 章节树可人工对照原图 |
| 公式是图 | 方法讲不清 | 公式图若被裁出则挂该节；讲不清就 `open_to_read_zh` | 不阻断报告 |
| 开 `generate_picture_images` 内存高 | worker OOM | 解析进程隔离；`images_scale` 默认 2.0；页图用完即卸 | 降级 PyMuPDF xref |

依赖：Python 3.11、FastAPI、PostgreSQL、Redis（异步任务）、Docling（主解析+裁图）、PyMuPDF（降级与 clip 兜底）、LLM endpoint。不依赖 GROBID、Qdrant、Asta Key、VLM。

## 8. 测试与验收标准

### 8.1 模块测试（无真实 PDF 二进制也可跑）

- 节选：fixture `sections.json` 含 Intro / Approach / Experiments / References → intro 不含 Approach 正文，method 不含 Experiments 长表。
- 节选 fallback：只有 `3. The Model` 这种非白名单标题 → method 仍非空且 `section_match=fallback`。
- 图绑定：阅读序 fixture 中 heading A → picture → heading B → picture，断言两张图分别挂 A/B。
- 过小图过滤：80px 以下不入库。
- 步骤挂图：`figure_ids` 含未知 id → 装配后丢弃；方法节有未引用图 → 仍出现在 `MethodExplain.figure_ids`。
- 引用核验：quote 不在该页 → 该步 `sourced=false`，`what_zh` 仍在。
- 扫描件：每页 10 个字符 → `needs_ocr`，不调用 `harness.complete`。
- harness：非法 JSON 重试一次后该产物 `failed`。
- 去重：同一 sha256 第二次 POST 不新增 paper 行、不重裁图。

### 8.2 集成测试

- 用 1 篇公开英文会议论文的抽文本 + 2 张占位 PNG fixture 跑 ingest → intro + method。
- 断言 intro 含非空 `one_sentence_zh`、`problem_zh`、至少 1 条 contribution。
- 断言 method 含 ≥3 条 `pipeline_steps`，每条有 `page > 0` 与 `section_title`。
- 断言方法节抽出的图出现在 GET method 的 `figure_ids` 或某一步 `figure_ids` 中。
- 断言 References 正文未进入两次 LLM 的 user 消息；prompt 中无 PNG/base64。

### 8.3 端到端验收（本期 MVP）

1. Web 或 curl 上传一篇 ≤ 15 页、含至少 1 张方法架构图的英文会议论文 PDF。
2. `GET /papers/{id}` 变为 `ready`，章节树能列出 Abstract、至少一个 method 类章节，以及该节下的图。
3. 打开「总体介绍」：中文问题/动机/贡献可读；若有总览图则显示裁出的 PNG。
4. 打开「方法详解」：能按步骤讲清模型/算法怎么走；页面上能看到从 PDF 裁出的原图（至少 1 张，只要原文方法节有图）。
5. 点击一步能看到页码和（若 sourced）英文摘录；图可放大对照题注。
6. 上传扫描件：界面说明需要文本型 PDF，不出现一本假介绍。
7. `audit_logs` 能按 `paper_id` 查到 parse/intro/method 的模型与 token、抽图数量。
