# 论文解析与翻译

> 对应实现：`src/dl_agent/knowledge/`（解析）、`src/dl_agent/translate/`（翻译）、`frontend/src/components/`（展示）。  
> 写法对照外部教程 [`agentic_rag.md`](https://github.com/)：每一步先讲**为什么**，再给带注释的代码。  
> **本文只写解析、翻译、对照阅读。** 工作区右侧的问答已落地，见 [`L2论文检索回答模块.md`](L2论文检索回答模块.md)；不要把本文理解成 RAG。

把一篇学术 PDF 变成「可点回原文的章节树 + 中英对照阅读」。不是再转一遍 Markdown，也不是把全文塞进一次 prompt。

```text
PDF
  → 解析（离线，可关 LLM）：阅读序 LayoutItem → Section[] + Figure[]
  → 翻译（按需）：按节切块 → 一次一块 LLM → 中文 + 图注
  → 展示：目录 + 章节原文（英/中）+ 原 PDF；点页码跳转，点图放大
```

现在能验收的是：上传后能看结构、能对照译文、能回到 PDF 那一页。解析完成后后台还会建检索索引（给问答用），细节不在本文。右侧「总体介绍 / 方法详解」仍是 M2，接口会 501。

**怎么读：** 先看 §0 和端到端 §21，再按「解析 → 翻译 → 展示」往下。阈值、HTTP 码、启发式散落在各节，末尾 §22 / §24 有汇总。

---

## 0. 为什么拆成解析、翻译、展示

用户要对照着看第 3.2 节，需要的是这一节的原文、图和中译，以及「点一下跳到 PDF 第 4 页」。

全文一次塞进模型会：

- 长文被截断，方法节常常排在后面，先被丢掉；
- 无法验收「这句话出自第几页」；
- 公式、表格、图标记被模型改写或丢掉；
- 关掉 API Key 就什么都看不到。

三段职责不同：

| 段 | 做什么 | 不做什么 | 失败时用户还能看什么 |
|---|---|---|---|
| **解析（离线）** | 得到稳定的 `Section` / `Figure`，带页码 | 不写中文、不回答问题 | 上传失败则什么都没有；解析失败可重传 / 重解析 |
| **翻译（按需）** | 按节生成中文，保住公式/表格/图标记 | 不检索、不摘要、不合并 Intro+Method | 英文章节树、图、原 PDF 仍在 |
| **展示** | 把节、图、译文画成对照阅读 | 不改解析结果；错位只在前端收拾 | 落盘 JSON 不变 |

关掉 LLM 也能看章节树、图和原 PDF。翻译是打开「中文」才跑。索引失败不影响对照阅读。

# 第一部分：PDF 解析

作用：上传后得到可阅读、可跳页的章节树和插图。这是后面翻译和展示的唯一输入。

## 1. 领域对象：后面都围着这三样转

**作用：**

- `Paper`：一篇论文的状态机（解析中 / 就绪 / 需要 OCR）
- `Section`：一个标题下的正文，翻译按节做，展示按节渲染，跳页用 `page_start`
- `Figure`：裁出来的 PNG，挂在某一节上
- `PaperTranslation`：按节对齐的中文；解析阶段还没有

```python
# src/dl_agent/domain/models.py（节选）

class Paper:
    paper_id: str
    sha256: str              # 同一文件再传一次，不重复解析
    filename: str
    status: str              # queued / parsing / ready / needs_ocr / ingest_failed
    parser: str | None       # "docling" 或 "pymupdf"，方便排查
    page_count: int
    figure_count: int
    title: str | None
    authors: list[str]
    abstract: str | None     # assemble 从 abstract 节抽出；没有则用首页 preamble
    language: str            # "eng" / "zho"（启发式）
    translate_status: str    # pending / ready / partial / failed / cancelled
    index_status: str        # pending / ready / skipped / failed（解析完成后自动建索引，给问答用）
    intro_status / method_status  # 现为 skipped；M2 接口仍 501

class Section:
    section_id: str          # 如 sec-003，assemble 时按出现顺序编号
    title: str               # "3.2 Loss Function"
    kind: str                # abstract / intro / related / method / experiment / conclusion / references / other
    level: int               # 1=章, 2=节（由 3.2 这种编号推；无编号则用 Docling tree_level，夹到 1–6）
    page_start: int
    page_end: int
    text: str                # 该节正文（含 $LaTeX$、表格 Markdown、<!--fig:fig-00N-->）
    parent_id: str | None    # 树：3.2 的父是 3
    figure_ids: list[str]

class Figure:
    figure_id: str           # fig-001
    section_id: str | None   # 挂在哪一节
    page: int
    kind: str                # figure / table_snapshot / algorithm / formula
    label: str | None        # "Figure 3" / "Algorithm 1"；去重键
    caption: str | None
    storage_key: str | None  # papers/{id}/figures/{fid}.png
    source: str              # docling_picture / pymupdf_xref / page_clip
    width_px / height_px
    bbox: tuple | None       # 点回 PDF 用；展示层目前只跳页，不高亮

class SectionTranslation:
    section_id: str
    title_zh: str
    text_zh: str
    partial: bool            # 切块中途失败
    chunks_done / chunks_total

class PaperTranslation:
    status: TranslateStatus
    model / prompt_version   # 换 translate-v10 → translate-v11 会作废旧译文
    title_zh: str | None     # 论文题名单独译一次
    sections / figures
    error: str | None
```

`kind` 是标题启发式，不是模型分类。翻译用它跳过参考文献。分类错了不致命，展示仍按阅读序排节。

`Figure.kind` 决定后续怎么用：

| kind | 从哪来 | 翻译 | 展示 |
|---|---|---|---|
| `figure` / `algorithm` | 插图 / 算法框图 | 译 caption | `FigureCard` + 灯箱 |
| `table_snapshot` | 被当成图的表 | 不入库为图 | 题注写进节正文，前端渲染 Markdown 表 |
| `formula` | 非法 LaTeX 的公式裁图 | 不译 caption | 当图显示，不当乱码字母 |

## 2. 上传、校验、去重

**作用：**

- 只接受真实 PDF（扩展名、`%PDF` 头、未加密、≤50MB）
- 同一文件用 sha256 去重，不重复解析
- 立刻返回 `paper_id`，解析在后台跑

入口是 `POST /papers`。HTTP 层只做上传，切节和裁图在 `KnowledgeService`。

```python
# src/dl_agent/api/routes/papers.py
# 1) 文件名必须以 .pdf 结尾（大小写不敏感）
# 2) 读入 bytes 后交给 start_ingest
# 3) should_parse=True → BackgroundTasks 跑 finish_ingest
# 4) 已是终态但 index 还 pending → 只补建索引，不再解析
```

```python
# src/dl_agent/knowledge/pdf_io.py
PDF_MAGIC = b"%PDF"

def validate_pdf_bytes(data: bytes, *, max_bytes: int) -> None:
    if len(data) > max_bytes:
        raise InvalidPdfError("PDF 超过大小上限")
    if len(data) < 8 or not data.lstrip().startswith(PDF_MAGIC):
        raise InvalidPdfError("不是有效的 PDF 文件")
    # PyMuPDF 再确认：能打开、未加密（空密码也打不开则拒绝）、至少一页
```

校验失败 HTTP **400** `invalid_pdf`。缺 PyMuPDF 同样当无效 PDF，因为后续降级和补洞都靠它。

`start_ingest` 的去重逻辑（持锁，避免并发上传同一文件打成两篇）：

```text
sha256(pdf)
  → 已有终态（ready / needs_ocr / ingest_failed）→ 直接返回旧 paper_id，should_parse=False
  → 进程中途挂掉的 queued/parsing → parsing 改回 queued，重新排队
  → 新文件 → 写入 data/papers/{id}/source.pdf，status=queued，index_sha
```

**为什么要去重：** 同一篇 PDF 再传一次，不该把章节树和图全部重做。重解析走单独的 `POST /papers/{id}/reparse`，显式忽略 sha256：把已有 `source.pdf` 重新 `queued`，清掉旧索引；若当前已是 `queued/parsing` 则不再插队。

`finish_ingest` 只处理 `status=queued` 的论文。先改成 `parsing`，再 `parse_fn`。已经是 `parsing/ready` 的调用会直接返回，防止后台任务重入。

| HTTP | 作用 | 失败码 |
|---|---|---|
| `POST /papers` | 上传，立刻返回 `{paper_id, status}` | 400 不是 PDF |
| `POST /papers/{id}/reparse` | 用已存 PDF 强制再解析 | 404 |
| `GET /papers/{id}` | 状态、页数、parser、题名 | 404 |
| `GET /papers/{id}/sections` | 章节树（**GET 时再跑一遍清理**） | 404 |
| `GET /papers/{id}/figures` | 可按 `section_id` 过滤 | 404 |
| `GET /papers/{id}/source` | `source.pdf`，inline 打开 | 404 |
| `GET /papers/{id}/figures/{fid}` | PNG 字节 | 404 |

## 3. PDF → 阅读序 `LayoutItem`

不要先压成一份 Markdown。先变成**带类型的阅读序流**，后面 `assemble` 才知道「这是标题 / 正文 / 图 / 公式」。

```python
# src/dl_agent/knowledge/layout.py

class LayoutItem:
    kind: str          # heading / text / table / caption / picture / formula
    page: int
    text: str
    level: int         # 仅 heading
    image_bytes: bytes | None
    width_px / height_px
    bbox: tuple | None
    caption / label
    source: str        # docling_picture / pymupdf_xref / page_clip
```

`ParseResult` 再包一层：用了哪个解析器、页数、题名、作者、语言。

```python
# char_count 只计 heading / text / table / caption，不计 picture / formula
# 这是「抽字够不够」的尺子，也是 needs_ocr 的输入
```

```text
parse_pdf(path)                         # adapters/pdf/__init__.py
  1. 试 Docling（关 OCR，开抽图）
     formula_enrichment=True 且 VLM 崩了 → 关 enrichment 再试一次
  2. char_count >= min_chars（默认 800）
        → PyMuPDF 三步补洞（失败只打日志）
        → 返回 Docling 结果
     char_count 太少 → 记下 sparse，改走 PyMuPDF
  3. Docling ImportError / 超时 / 崩溃 → PyMuPDF
```

## 4. 主路径：Docling

**作用：**

- 版面分析给出阅读序（双栏不会左右拼成乱句）
- 一次 convert 同时出标题树和插图 PNG
- 表格导出成 Markdown，前端能渲染

**文档：**

- [Docling](https://github.com/docling-project/docling) — PDF 版面分析与结构化抽取

关键选项（`docling_adapter.py`）：

```python
PdfPipelineOptions(
    do_ocr=False,                  # 扫描件不做 OCR；字太少就标 needs_ocr
    do_table_structure=True,       # 表格结构，不只是格子图
    generate_picture_images=True,  # PictureItem → PIL → PNG
    do_formula_enrichment=False,   # 默认关；开了是 VLM 公式，慢且易超时
    images_scale=2.0,              # Settings.images_scale
    document_timeout=timeout_s,
)
```

`do_ocr=False` 是有意的：主路径要快、可重复；扫描件走 `needs_ocr`，不假装已经读懂，也不拿去翻译。`do_formula_enrichment` 默认关，公式走后面的规则 + 可选视觉，而不是绑死 Docling 自带 VLM。

`ConversionStatus.FAILURE` 或 `has_timeout_errors()` → `ParseError`，触发降级。

| Docling 元素 | LayoutItem.kind | 备注 |
|---|---|---|
| `PictureItem` | `picture` | PNG + `caption_text`；`source=docling_picture` |
| `TableItem` | `table` | `export_to_markdown()`，兼容不同签名 |
| `FormulaItem` 或 label=formula | `formula` | 先留 LaTeX；乱码则留 `orig`；像散文且不像公式 → 改 `text` |
| `section_header` / title | `heading` | `tree_level` → 层级；首页 title 同时当论文题名 |
| caption | `caption` | 后面绑到最近的图 |
| 普通 `TextItem` | `text` | `page_header` / `page_footer` / `footnote` 丢掉 |
| 其它 | 跳过 | 不进阅读序 |

页码来自 `element.prov[0].page_no`，bbox 取 `(l, t, r, b)`。展示里「点 p.4 跳 PDF」靠的就是这个；纯 Markdown 通常没有可靠页码。

语言：前 40 个 item 的文本里 CJK > 20 则 `zho`，否则 `eng`。只写进 `Paper.language`，不改变翻译策略（翻译始终要求简体中文）。

## 5. 降级：PyMuPDF，以及 Docling 成功后的三步补洞

**作用：**

- Docling 没装、超时、或抽字过少时，章节树仍能用
- 即便 Docling 成功，学术 PDF 仍常漏图、把公式当成乱码字母

降级路径（`pymupdf_adapter.py`）：

- 按页 `get_text("dict", sort=True)`；
- 字号中位数 `median`，标题阈值 `max(median * 1.18, median + 1.2)`；
- 或匹配 `Introduction` / `Method` / `References` 等词表（可带 `1.` / `IV.` 编号）；
- 正文长度 > 120 不当标题；纯字号命中时长度 ≤ 90；
- 页眉页脚：距页顶/页底 < 36pt 且长度 < 80 丢掉；
- 内嵌图走 xref（`source=pymupdf_xref`）；题注在图下方 80pt 或上方 80pt 里用 `Figure N` 正则找；
- 题名：首页上半页字号最大、长度 ≤ 180 的一行。

没有 Docling 的版面模型，双栏和公式会差一截。`Paper.parser` 会记 `"docling"` 或 `"pymupdf"`。

主路径成功后还会跑三步（失败只打日志，不让整篇 ingest 失败）：

```text
1. clip_missing_captions
   正文里有 Figure 3 题注，但没有对应 picture
   → 先回头看同页、题注前 10 个 item 里有没有未标注插图，有则绑 label
   → 没有则在题注上方 clip（默认高出 280pt，Settings.clip_above_pt）
   → 裁出宽高都 ≥ 80px 才收；source=page_clip
   → Table 题注不当图

2. clip_formula_items
   给还没有 PNG 的 formula 项按 bbox 裁图（外扩 3pt，拒绝超过页高 35% / 页宽 95%）
   → 去白边；宽 < 24 或高 < 16 丢掉
   → 后面视觉模型才能「看图识公式」；展示也能先看到图

3. inject_inline_math
   扫描 PDF 里的数学字体（CMMI、CMSY、STIX、Cambria Math…）
   → 把连续 math span 收成 LaTeX
   → 已和 formula 框 overlap>0.2 的跳过（避免写两遍）
   → 纯斜体单词且没有上下标的跳过（避免把 emphasis 当公式）
   → 嵌回最近的 text 项
```

精读界面要用 KaTeX 渲染公式，所以解析阶段就要把符号收成 LaTeX，不能等翻译时再猜。

## 6. 公式三层：规则 → 裁图 → 视觉

**作用：** 尽量得到可渲染的 LaTeX；实在不行就显示裁图，不把 `????` 留给读者。

```text
formula LayoutItem
  → 已是合法 LaTeX？ → 写入节文本 $$...$$ 或 $...$
  → 乱码 / 括号不配 / 残式（如 L_g L_CE L_Tri 中间运算符丢了）
        → 若有裁图且配置了视觉模型 → JSON {"latex":"..."}
        → 否则保留 PNG，正文里插 <!--fig:fig-00N-->
```

独立公式还是行内，看 bbox：高 ≥ 18 或宽 ≥ 120 → display（`$$`），否则 inline（`$`）。只有方程号 `(3)` 的项不当公式。

判断「要不要看图」在 `formula_latex.py`：

```python
# 三道闸，从宽到严

def is_garbled_math(text):
    # U+FFFD、\backslash、私用区 U+E000–F8FF

def looks_like_latex(text):
    # 有 \、_{、^{}，或字母带上下标 → 像公式
    # 乱码或纯 (n) 不算

def is_renderable_latex(text):
    # 括号配对、没有双重上下标、没有粘连命令（\timesxxx）
    # 没有未转义 Unicode 运算符（∈∑）
    # 过不了的交给视觉重识别

def latex_needs_vision(text):

        return True
    return latex_looks_incomplete(text)
    # 渲染得出但结构残缺：≥3 个标识符却没有 = / 运算符 / \in / 括号
```

视觉补救在 `formula_vision.py`，**ingest 里、assemble 之前**跑：把公式 PNG 发给多模态模型，**只改 `item.text`**，图仍留给 UI。

```python
SYSTEM_PROMPT = """You transcribe formulas from academic PDF crops
into KaTeX-compatible LaTeX.

Return ONLY JSON: {"latex":"..."}
- Copy the formula in the image exactly. Do not invent symbols.
- Do not wrap the latex in $ or $$.
- Use \\tag{n} for a trailing equation number like (3).
- If the image is not a formula, return {"latex":""}.
"""
```

哪些 formula 会送视觉：

1. `latex_needs_vision(text)`；或
2. 有 bbox 且是 display 公式（启发式过不了「能渲染但抽错」）；或
3. 下一项正文里漏进了 `\\tag{` / `X_{yy} =`（公式泄漏到散文）

送的时候带前后各 2 个 text/heading/caption 当 context（合计 ≤500 字）。旧 LaTeX 若已经可渲染且 `latex_score` 更高，新结果丢掉。成功后会从后文抠掉泄漏的赋值/`\tag`。

没配视觉模型或关闭 `FORMULA_VISION_ENABLED` 时跳过，解析照样 `ready`。上限 `FORMULA_VISION_MAX=80`，超时默认 60s。模型解析：

```text
FORMULA_VISION_MODEL 显式指定
  → 否则主模型名带 vl / gpt-4o / gemini / deepseek-flash
  → 否则 base_url 含 dashscope → qwen-vl-plus
  → 否则 api.deepseek.com → deepseek-flash
  → 再没有 → 整段跳过
```

`latex_score`：`=` ×3，再加上 `+`、括号、`\mathcal`、`\mathbb`、`\in`、`\times`、`\oplus`、`\tag`。更差的结果丢掉。返回 JSON 里若出现超长英文单词（去掉 `\` 命令后仍 ≥12 字母）视为模型在瞎写，丢弃。

正文里的公式排版由 `layout.tidy_math_prose` 做：拆开 `$` / `$$`、把碎片公式拼回去、把 `x_m^i` 包进行内数学、把 `QVT ∈ ℝ` 收成 `Q_T^V \in \mathbb{R}`（跳过 CNN/MLP/BERT 这类缩写）。细节全是启发式，目标是前端 KaTeX，不是做一个完整 TeX 引擎。GET 译文时还会再跑 `tidy_translation_math`（给中文里的裸 `\in` 补 `$`，并把误包进公式的「其中」撕出来）。

assemble 时公式入节：

```text
合法 LaTeX 且不是 (n)
  → display：单独成段 $$ latex $$
  → inline：接到上一句后面 $latex$
否则若有图且宽≥90、高≥16
  → kind=formula 的 Figure + <!--fig:fig-00N-->
否则丢掉（没图又没 LaTeX，写进去也是乱码）
```

`polish_formulas` 会丢掉宽 < 90px 的公式碎片图，并从节文本里拿掉对应标记。

## 7. `assemble`：阅读序 → 章节树 + 挂图

这是解析的核心算法：按 **heading 开新节，picture 挂到当前未关闭的节**。

文件：`src/dl_agent/knowledge/layout.py` 的 `assemble()`。

**作用：**

- 维护一个节栈（像 HTML 标题层级）
- 正文追加到栈顶
- 图绑定 `section_id`
- 参考文献之后的附录默认不再入库（少译、少展示噪声）

```text
stack = []                    # 当前打开的节，末尾是「正在写的节」
after_refs = False
skip_until_heading = False    # 致谢正文丢掉，直到下一个标题

遇到 heading:
    致谢 / Acknowledgements / running title → skip_until_heading=True
    像 "challenge." 这种假标题（小写、句号结尾、≤8 词）→ 并回上一节正文
    第一页未编号、且不像 Abstract/Intro → 当作论文标题，不开节
    References → 开节，after_refs=True，只再收参考文献正文
    否则 close_to(level)，开新 Section

遇到 text / table:
    页眉页脚 / 对应作者脚注 / 会议 OA 句 → 丢掉
    追加到当前节；还没有节 → 开 "Front Matter"
    连续列表项用单换行，普通段落用空行
    整段已经出现过（或 >48 字的片段已在节内）→ 只更新 page_end，防双栏重复

遇到 caption:
    已有 Figure N 标签且不是表 → 丢掉（避免题注写两遍）
    否则当正文

遇到 formula:
    见 §6

遇到 picture:
    宽或高 < min_figure_px（默认 80）→ 当 logo 丢掉
      （page_clip 且没有像素、但有 label/caption 的仍留下，给去重用）
    当前 item 没有 caption → 往后看同页最多 5 个 item
    Table 题注 → 只保留题注文字，不当图
    否则裁 PNG，figure_ids 挂到当前节
```

参考文献条目常被拆成 `[1]` 和作者行两块，`_glue_ref_number` 会粘回 `[1] Author...`。

节的层级：标题 `"3.2 Loss"` → `level=2`（数点号）。罗马数字 / 单字母编号走 `tree_level`。栈的 `close_to` 保证 3.2 结束时弹出，3.3 与 3.2 同级，而不是挂在 3.2 下面。

```python
def close_to(level: int) -> None:
    while stack and stack[-1].level >= level:
        stack.pop()

def open_section(title: str, page: int, level: int) -> Section:
    close_to(level)
    parent = stack[-1] if stack else None
    section = Section(
        section_id=f"sec-{len(sections) + 1:03d}",
        title=title.strip(),
        kind=classify_kind(title),   # 正则：abstract / method / ...
        level=level,
        page_start=page,
        parent_id=parent.section_id if parent else None,
        ...
    )
    stack.append(section)
    return section
```

节类型是标题启发式（先去掉 `1.2` / `IV.` 再匹配）：

```python
# src/dl_agent/knowledge/classify.py
_KIND_RULES = [
    ("abstract",    r"\babstract\b|摘要"),
    ("intro",       r"\bintroduct|\bbackground\b|\bmotivation\b"),
    ("related",     r"related work|prior work|literature review"),
    ("method",      r"\bmethod|\bapproach\b|\bmodel\b|\barchitecture\b|\bproposed\b|\bframework\b"),
    ("experiment",  r"\bexperiment|\bevaluat|\bresult|\bablation"),
    ("conclusion",  r"\bconclusion|\bdiscussion\b|\blimitation"),
    ("references",  r"\breferences\b|\bbibliography\b|参考文献"),
]
# 都不中 → other
```

`method` 规则很宽（含 `model`），所以首页长标题里出现 Method 时，要靠 `looks_like_paper_title_heading` 拦住：未编号、不是 Abstract/Intro、且（不是短的 method/experiment 标题）。

装配结束后还有清理，**GET 章节/插图时也会再跑一遍**，所以旧数据刷新页面也能修好，不必重解析：

| 函数 | 做什么 |
|---|---|
| `apply_figure_dedupe` | 同一 `Figure 3` 只留一张；优先非 `page_clip`、有 PNG 的 |
| `polish_formulas` | 丢掉过小的公式碎片图；`tidy_math_prose` + 去掉对应作者脚注 |
| `collapse_false_headings` | 已经落盘的断行假标题并回上一节，图也跟过去 |
| `repair_front_matter` | 跑题 `Abstract—` 拆成独立 abstract 节；IEEE「are with / corresponding author」从引言挪回作者区；段首 drop-cap `T He` → `The` |

摘要：优先 abstract 节正文；没有则用首页、assemble 前攒下的 preamble，长度在 80–4000 之间才当 abstract。

字数门槛（`finish_ingest`）：

```text
chars = ParseResult.char_count
per_page = chars / page_count
page_count<=0 或 chars < 800 或 per_page < 200
  → status=needs_ocr
  → intro/method/index 标 skipped
  → 不进入翻译
```

扫描件没有可靠文本，译文会编造。`needs_ocr` 仍会保存已抽出的节和图，方便用户先看「抽到了什么」。

## 8. 落盘：解析产物就是翻译和展示的输入

```text
data/
  index.json                          # sha256 → paper_id
  papers/{id}/
    source.pdf                        # 展示「原PDF」用
    paper.json                        # 状态、页数、parser、题名
    sections.json                     # 章节阅读 + 翻译都读这里
    figures.json
    figures/{fid}.png                 # 节内插图 / 灯箱
    translations.json                 # 译文；解析阶段还没有
    chunks.json / 向量库              # 问答用，对照阅读不读
```

`FilePaperStore` 只存 JSON + 文件。键按 S3 风格 `papers/{id}/...`。写入走临时文件再 `os.replace`，避免写到一半崩溃留下半份 JSON。`list_papers` 按 `paper.json` 修改时间倒序。

解析失败不影响已经裁出来的图（失败发生在 assemble 之前则可能还没有图）；翻译失败不影响章节树。重解析会 `delete_figures` 再写，避免旧 fig-001 和新图对不上。

`finish_ingest` 成功后：

- `status=ready`（或 `needs_ocr` / `ingest_failed`）
- `translate_status=pending`（用户打开中文才跑）
- `intro_status` / `method_status` = `skipped`（M2 未接）
- 若这篇以前译过，删掉旧 `translations.json`（章节树变了，旧译文对不上）
- `ready` 则立刻 `index_paper(force=True)`；`needs_ocr` 则 `index_status=skipped`

到这里，关掉 LLM 也能在工作区看到目录、章节原文、图和 PDF。

# 第二部分：把解析结果译成中文

作用：按节把英文变成简体中文，公式仍能渲染，图注也能对照。**按节确定性生成，不是检索问答。**

## 9. 为什么按节译，而不是整篇一次、也不是问答

翻译要的是「每一段都在」，和问答正好相反：问答可以只抽出相关几句，翻译漏一段就是产品缺陷。

| | 章节翻译（本文） | 论文问答（另一条链路） |
|---|---|---|
| 输入 | 整节 `Section.text` | 用户的一个问题 |
| 输出 | 与原文等长的中文 | 一段回答 + 引用 |
| 漏内容 | 不行 | 可以 |
| 切块 | ~1200 字，为了不超 token | Parent–Child 索引，见问答文档 |

```text
先单独译论文题名（作者名禁止翻译）
for section in sections:
    if 参考文献 / 致谢 / 空节 / 作者栏:
        跳过（标题可写成「参考文献」，正文保持英文）
    else:
        切块 → 每块一次 LLM → 拼回 text_zh
然后批量译图注
```

切块只是把超长方法节拆开，避免一次 prompt 超时。没有向量库。

## 10. 入口与状态机

**作用：**

- 打开「中文」或点「重新翻译」才调用 LLM
- 刷新页面、进程重启后能续跑
- 换 prompt 版本后旧译文作废

HTTP：

```text
POST /papers/{id}/translations              开始或续跑
POST /papers/{id}/translations?refresh=true 丢掉旧译文，整篇重译
GET  /papers/{id}/translations              轮询进度（pending 也返回已译章节，不 202）
POST /papers/{id}/translations/cancel       终止当前 run
```

| 情况 | 码 |
|---|---|
| 论文不存在 | 404 |
| `paper.status != ready`（排队 / OCR / 失败） | 409 `not_ready` |
| 未配置 `OPENAI_API_KEY` | 503 `llm_not_configured` |
| 尚未开始翻译就 GET | 404 |
| cancel 时还没有 translations.json | 404 |

状态：

| status | 含义 | 展示 |
|---|---|---|
| `pending` | 正在跑；已完成的节已写入 JSON | 进度条，英文仍可看，可停止 |
| `ready` | 该译的节都有中文 | 对照阅读 |
| `partial` | 部分节失败 | 失败节显示英文 |
| `failed` | 一次都没成功（或题名就 fatal） | 错误提示，英文仍可看 |
| `cancelled` | 用户点了停止 | 保留已译章节，可继续 |

`run_id` 单调递增。点「重新翻译」会作废旧 run（给旧 `threading.Event` set），避免两路互相覆盖。GET 时：`pending/cancelled` **即使 prompt 版本旧也返回**，否则前端轮询会 404；其它状态若版本不一致则当「尚未开始」。

```python
# src/dl_agent/translate/service.py（方法示意）

def start_translation(self, paper_id, *, refresh=False):
    if paper.status != "ready":
        raise ValueError("paper_not_ready")          # 扫描件 / 解析失败不译
    if 已有 ready/partial 且版本相同且图注、该译的节都齐:
        return cached, should_run=False              # 幂等
    if pending 且进程里还在跑:
        return cached, should_run=False              # 只轮询
    if pending 但是进程已经死了:
        return cached, should_run=True               # 续跑
    if cancelled（非 refresh）:
        保留已译章节，再排队
```

`finish_translation` 发现 `run_id` 不是当前值就直接退出（stale run）。每完成一节立刻写 `translations.json` 并把 `Paper.translate_status` 保持 `pending`。

## 11. 哪些节不译

**作用：** 少花 token，也不把参考文献译成一堆「张三，某某学报」。

```python
def _skip_section(section: Section) -> bool:
    if not section.text.strip():
        return True
    if section.title.strip().lower() == "front matter":
        return True                              # 作者栏、单位、会议页眉
    if _is_paper_title_section(section):
        return True                              # 第一页、无编号、正文像作者单位
    if section.kind == "references":
        return True
    if "acknowledgement" in section.title.lower() or "致谢" in section.title:
        return True
    return False
```

「像作者单位」：`level==1`、`page_start==1`、不是 abstract/intro/related/conclusion/references，标题无编号，正文匹配 `@` / university / corresponding author / 学院 / IEEE。短 method/experiment 标题除外。

跳过的节仍在 `translations.json` 里占一项（`text_zh` 用英文原文，参考文献标题写成「参考文献」），前端按 `section_id` 对齐，不会缺节。论文题名单独译一次，要求至少 2 个汉字且不是原文拷贝；作者名禁止翻译。

## 12. 切块：保护公式，不在 `$` 中间断开

**作用：** 方法节经常超过模型上下文。切块必须：

- 优先在段落边界（`\n\n`）断开；
- 一段仍超长再硬切，但 **`$...$` / `$$...$$` / `\begin{align}...\end{align}` / 带下标的短括号式** 视为保护区；
- 记下这块是不是段落开头，拼回去时才知道要不要插空行。

默认 `TRANSLATE_CHUNK_MAX_CHARS=1200`，服务层下限 400。节与节之间默认再隔 `translate_section_delay_s=0.5` 秒，减轻限流。

```python
@dataclass(frozen=True)
class TextChunk:
    text: str
    paragraph_start: bool = True   # False = 从一段中间切断，拼回时不加 \n\n

def _split_text_chunks(text: str, max_chars: int) -> list[TextChunk]:
    if len(text) <= max_chars:
        return [TextChunk(text)]
    chunks = []
    for paragraph in re.split(r"\n\n+", text):
        if len(paragraph) <= max_chars:
            chunks.append(TextChunk(paragraph))
        else:
            chunks.extend(_hard_split_text(paragraph, max_chars))
    return chunks
```

硬切时先标出保护区。切点若落在保护区内：能往前收到保护区起点就收；整段保护区比 `2 * max_chars` 还长才允许从中间切开（极端公式块）。切点优先级：空行 → 换行 → `.?!。` → 空格。

翻译是顺序拼接，**不要 overlap**：重叠会造成同一句中文出现两次。保护区已经保证公式不会被拦腰切断。

单块直接走「整节 prompt」（同时出 `title_zh` + `text_zh`）；多块时只有第 0 块带标题，后面的块只译正文。中途失败会把 `partial=True, chunks_done=N` 写进 JSON，再 POST 从第 N 块续跑。已缓存且 `_looks_like_chinese` 的整节会跳过。

## 13. Prompt 与结构校验：模型不能随便改版式

**作用：** 学术翻译最常见的失败不是「用词不准」，而是版式坏了，对照阅读对不齐：

- 把英文原样抄回来；
- 丢掉 `$$` 或 `<!--fig:fig-003-->`；
- 把三段并成一段；
- 公式乱码原样留下，KaTeX 渲染失败。

System prompt 的硬约束（`translate-v10`）：

```text
- 必须简体中文，禁止抄英文原文，禁止摘要/删段
- 公式必须是可渲染的 KaTeX；PDF/OCR 乱码要修好
  例：b proj ∈ RC_v  →  $b_{\mathrm{proj}} \in \mathbb{R}^{C_v}$
- 独立公式用 $$...$$，行内用 $...$；$$ 个数与原文相同
- 不要把「其中 / 表示 / 是」包进 $...$
- 段落空行（\n\n）与原文一致
- 保住 markdown 表格、列表、<!--fig:fig-N-->、[1] 引用、模型/数据集名
- 只返回 JSON，不要 markdown 围栏
```

每次调用要求的 JSON：

```json
{"title_zh":"损失函数","text_zh":"...中文..."}
```

围栏 ` ```json ` 会被剥掉再 parse。

译完不是直接落盘，而是走一遍结构检查，不行就再请模型修一次：

```python
def _structure_issues(source, translated) -> list[str]:
    issues = []
    if 原文 $$ 块数 != 译文 $$ 块数:
        issues.append("display-math")
    if 原文段落数 > 1 且译文段落更少:
        issues.append("paragraphs")
    if 原文的 <!--fig:...--> 集合 != 译文:
        issues.append("figure-markers")
    return issues
```

另外还有内容闸：

| 问题 | 判定 | 是否致命 |
|---|---|---|
| `empty` | `text_zh` 空 | 是 |
| `verbatim` | 译文 == 原文，且原文拉丁字母 ≥40、不是公式/表为主 | 是 |
| `not_chinese` | 去掉公式/表/图标记后汉字太少 | 是（markup 为主时放宽） |
| `display-math` / `paragraphs` / `figure-markers` | 结构对不齐 | 否，可保留 |

「像中文」：去 markup 后 ≥4 个汉字；或短句（≤40 字）有 ≥2 个汉字；或原文公式/表格/图标记 ≥45% 且拉丁字母 <120。公式/表格占正文大部分时，汉字很少是正常的，不判失败。

致命问题会触发结构重试 prompt（明确告诉模型需要几个段落、几个 `$$`）。非致命保留译文，避免整篇卡死。重试仍致命则该节失败，整篇可能变成 `partial`。

## 14. 并行、取消、续跑

**作用：** 方法节多、公式多时，串行会跑十几分钟；用户必须能中途停。

```text
TRANSLATE_PARALLELISM=1     默认串行，稳；可调到 2–4
TRANSLATE_CHUNK_MAX_CHARS   默认 1200（下限 400）
LLM_TIMEOUT_S               默认 180
LLM_MAX_RETRIES             默认 4（harness）
```

并行按**节**并发（`ThreadPoolExecutor`），一节内部的块仍顺序译。完成一节立刻写入，前端轮询就能看到新译文。取消靠 `threading.Event`，传进 `chat()`，正在飞的 HTTP 也会停。`_wait_or_cancel` 让节间 delay 也能被打断。

「重新翻译」会作废旧 `run_id`，并清空已译章节 / 题名 / 图注。非 refresh 的 cancelled/partial 续跑会 `reuse_cache`。

## 15. 图注：先从译文里收割，不够再单独译

**作用：** 图注经常已经出现在某节正文里（「图 1. 总体架构」）。能收割就不再花一次 LLM。公式图（`kind=formula`）没有 caption，不译。

```text
1. 收集所有带 caption 且 kind != formula 的 Figure
2. 已有中文图注 → 保留
3. 从各节 text_zh 里用「图 N / 算法 N」对上 figure.label
4. 仍缺的，打包成一次 JSON：
     {"captions":[{"figure_id":"fig-001","caption_zh":"图 1. ..."}]}
```

模型若把 `figure_id` 写成 `1` / `fig-1` / `Figure 3`，会用别名表折回 `fig-003`。返回里没有汉字的 caption 丢掉。像素不送给翻译模型——图已经是 PNG，展示层直接显示。

前端在 `ready/partial` 后若发现还有未译图注，会再 POST 一次（非 refresh）触发补译。

## 17. 打开「中文」才开始翻译

`PdfPane` 里英 / 中是两个独立开关，可以只看英文、只看中文、或对照。关掉中文会 bump `pollGeneration`，正在飞的轮询作废。

```text
默认：英文开、中文开
  → GET translations
       404 → POST 开始
       cancelled → 显示已译章节，提示可继续
       pending → POST 续跑（可能是进程重启后的僵尸任务）
  → 每 2.5s GET 一次，已译的节立刻插入对照
  → 进度：翻译中 3/12；可停止 / 继续 / 重新翻译
  → 章节数 60s 不变 → 「当前章节较长」
  → 约 5 分钟不变 → 再 POST 续跑（防服务重启）
  → 约 15 分钟仍 pending → 提示超时，请点重新翻译
```

没开中文时不打翻译接口。预览 Demo 用本地写死的译文，不走后端。`pollGeneration` 防止停止/切换语言后旧请求写回状态。

解析未 `ready`（排队、失败、需要 OCR）时不能译；界面继续显示已有英文结构或错误芯片。

## 18. 一节如何画成对照块

阅读器先把英文 `section.text` 切成块，再给中文配上去。文件：`SectionReader.tsx`、`lib/mdTable.ts`、`lib/bilingual.ts`、`MathText.tsx`。

```text
section.text
  → 按 <!--fig:fig-00N--> 切开，插入对应 PNG
  → 正文里提到 Figure N / Algorithm N 且尚未插入过 → 补一张
  → markdown 表格抽出；表题、表注、罗马数字 Table I 对齐
  → 连续 (1) / 1. / - 收成 list 块
  → 独立公式 $$...$$ 单独成块（KaTeX）
  → 剩下的是段落
  → 中文 text_zh 同样切开
  → 段落配对（pairBilingualProse）
  → where / 其中 再对齐（realignWhereSegments）
  → 丢掉译文开头没有汉字的公式碎片（dropLeadingZhDebris）
```

`layoutPaperMedia` 按整篇做一次，避免同一张图在相邻节里出现两次。

块类型：

| 块 | 英文怎么来 | 中文怎么来 |
|---|---|---|
| 段落 | 正文 | 按序配对；`where` / `in which` / `here,` 优先配「其中 / 式中」 |
| 独立公式 | `$$...$$` 或公式裁图 | 公式只渲染一次（英文侧）；中文丢掉重复源码，只留「其中 λ 为…」 |
| 表格 | markdown table | 按表题「Table 1 / 表 1」对齐；对不上再按出现顺序 |
| 插图 | `<!--fig:...-->` 或题注提到 Figure N | 同一张 PNG；题注用 `caption_zh` |
| 列表 | `(1)` / `1.` / `-` | 按项配对 |
| 参考文献 | `splitReferenceEntries` 按条目切开 | 通常不译，仍显示英文 |

标题行是 `英文标题` + `中文标题`，右侧 `p.4–5` 调用 `onJump(page, section_id)`：切到原 PDF，并滚动到该节。

Front Matter / 标题节不进正文流：题名、作者单位提到文章最上方。`isMetaSection` 用页码、编号、作者单位启发式判断。

## 19. 对照为什么不能「第 i 段对第 i 段」

模型偶尔会把「公式 + where λ is …」译成「公式。其中 λ 为 …」，段落数对不齐。前端必须能把「where」配到「其中」。

```text
pairBilingualProse:
  1. 英文 where 段 优先配 中文「其中」段
  2. 剩下的按出现顺序配
  3. 仍有英文 where 没配上 → 从上一句中文末尾撕下「其中…」

realignWhereSegments:
  英文是「导语 + 连续公式 + where」时，
  跳过中间的纯公式段，把写在公式前的「其中」接到 where 上
  公式 LaTeX 里误带汉字 → peelHanFromLatex
```

这是展示层启发式，**不回写** `translations.json`。后端仍要求段落数尽量一致；前端负责收拾残余错位。

独立公式只在英文侧用 KaTeX 画一次。中文若再带一份 `$$...$$`，会和英文公式重复，所以 `stripDisplayMath` 把译文里的独立公式源码丢掉。纯公式、没有正文的英文块（`isMathOnlyText`）不消耗一段中文译文。

行内公式：`MathText` 把 `$...$` 交给 KaTeX；译文里夹着的裸 `\in`、`\frac` 会先 `wrapBareInlineMath`。误把「其中…」包进 `$` 的，`unwrapHanMath` 拆出来，避免整句进 KaTeX。

## 20. 图和 PDF 怎么点回去

插图是解析裁出的 PNG，不是模型画的。

- 节内用 `FigureCard` 显示缩略图 + 题注（英/中随开关）；
- 点击打开灯箱（`Lightbox`），仍是同一张 PNG；
- 公式若没有合法 LaTeX，节里出现的是公式裁图，而不是乱码字母。

原 PDF：

- `GET /papers/{id}/source` 返回 `source.pdf`；
- `PdfPane` 在「原PDF」模式下用 pdf.js 渲染当前页；
- 目录、章节 `p.N`、图上的页码都写同一个 `page` 状态。

展示层不根据 bbox 在 PDF 上画高亮框；先做到跳页。bbox 留在 `Figure` 上，以后要精确框选再用。

## 21. 端到端：一篇论文从上传到对照阅读

```text
POST /papers
  校验 PDF → sha256 去重 → queued
  finish_ingest（后台）:
      Docling / PyMuPDF → LayoutItem[]
      clip 漏图 / 公式框 / 行内数学字体
      公式视觉修复（可选）
      assemble → sections.json + figures/*.png
      ready | needs_ocr | ingest_failed
      解析 ready 后自动 index_paper（问答用，见另一文档）

工作区
  左：GET sections → 目录（GET 时再 collapse / dedupe / 修首页）
  中：章节原文（默认英文）
  切到原 PDF → GET source，按页渲染

打开「中文」
  POST translations → 按节切块翻译 → 每 2.5s 轮询 GET
  已译的节插入对照；图注随后补上
  点 p.4 → 原 PDF 第 4 页
```

三步失败互不影响：解析失败不译；翻译失败仍能看英文和图；展示坏了不改 JSON。

问答走另一条链路（`POST /papers/{id}/ask` 等），不要把本文理解成 Agentic RAG。索引失败不影响对照阅读。

## 24. 已知边界（不是 bug 清单，是产品范围）

这些是实现里**故意不做**或**只做到这一步**的地方，改需求前先看这里：

- **扫描件**：不跑 OCR。`needs_ocr` 后禁止翻译，避免编造。
- **双栏降级路径**：纯 PyMuPDF 没有版面模型，阅读序会差；主路径必须是 Docling。
- **参考文献之后**：附录、补充材料默认丢弃，减少翻译噪声。
- **bbox 高亮**：字段在，UI 只跳页。
- **作者名**：题名可译，作者单位节整节跳过。
- **表格**：当 Markdown 渲染，不当图片（`table_snapshot` 丢掉像素）。
- **公式视觉**：最多 80 条；失败不影响 `ready`。
- **对照错位**：后端尽量对齐段落/`$$`；残余 where/其中 只在前端修，不回写。
- **M2**：`/intro` `/method` 仍 501。
- **单机文件存储**：无多用户锁之外的对象存储；并发上传同一 sha256 靠 `KnowledgeService._lock`。
